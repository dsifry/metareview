What it does

Four ways metareview makes your code trustworthy.

Whether you write the code or your AI agent does, metareview is the rigorous second pass that turns "looks done" into "proven done" — keeping your code, reviews, and lessons in your own repository.

Install it Full technical guide
1 · Review

Catch problems before they ship.

A structured second pass at the moments that matter.

metareview reviews the things that decide quality — the plan before work starts, each change as it's finished, and the whole branch before it merges. Multiple independent reviewers look for missing tests, security gaps, work that drifted from the original goal, and edges nobody thought about.

The result isn't a vague "looks good." It's a clear verdict with specific blockers that stay on the to-do list until they're genuinely fixed — so nothing important gets waved through.

2 · Find & fix — with proof

Bugs found, fixed, and proven gone.

The part you can never quite trust from an AI — solved.

metareview runs a loop that finds a bug, confirms it's real, fixes it, and then proves the fix: it writes a test that fails on the old code and passes on the new one, and runs it for real. If a fix can't be proven, it doesn't count as done.

That's the difference between "the AI says it fixed it" and "here's the evidence it's fixed." Every judgment along the way is recorded, so you can always see what was decided and why.

3 · Test deeply

Make sure the important code is really tested.

"The tests pass" isn't the same as "this is tested."

A test suite can run every line and still check almost nothing. metareview uses mutation testing — it deliberately breaks the code in small ways and watches whether your tests notice. The breaks nobody catches are exactly the gaps that let real bugs through.

Point it at the code that matters most, and it drives those pieces toward genuine, exhaustive coverage — not the superficial kind.

4 · Learn locally

It gets smarter about your project — privately.

Your code and your lessons stay on your machine.

After work merges, metareview records the durable lessons — the repo-specific gotchas, the decisions, the mistakes worth not repeating — as plain Markdown in your own repository. Future reviews start smarter.

Unlike hosted review services, your reviews and lessons live in your own repo as plain Markdown — not locked inside a vendor's database. (The AI model you choose as the reviewer does see the review context you send it, following that provider's data-handling rules.)

A review is not a vibe check. It is a state transition.

Works with your stack and your AI.

No lock-in — to a language or a model.

Languages: Go, TypeScript (Jest or Vitest), and Python work out of the box, reading each test runner's own results.

Models: use Claude, GPT, GLM, or Kimi as the reviewer, and switch per run. Every review is recorded so decisions are auditable.

Where it runs: git-native, in your own repo — your code, reviews, and learning stay with you. External model calls follow the data-handling rules of whichever provider you pick.
