## 1. The problem, and why it gates Ship 1

`Unproven` clears and re-adds a gap by **`Pin.Finding`** — the confirmed-finding id (spec §2.4). A fix
that regressed and is re-discovered must land back in `Unproven` under the **same** id, or its gap is
never re-opened and `pins_proven` passes vacuously (the #24 self-clearing shape, one level up). So the
finding id must be **stable across rounds**: the same fault, re-surfaced, must hash to the same id.

Two failure directions:
- **Recall (the actual blocker):** the same fault, **reworded** across rounds (a paraphrase), must NOT
  get a new id. If it does, the old gap never clears and the class never continues — a false split.
- **Precision (already measured):** two **distinct** faults must NOT collapse to one id. The §5 spike
  measured this direction only: `(file, normalized-text)` gave **0% false-merge over 611 findings**.

The recall direction is **unmeasured today** — there is no paraphrase ground truth in the corpus and no
protocol in §5/§7/§8. That measurement is the spike; the algorithm shape is already fixed by §9.8 R6
(a tuned lexical key beat deep-embeddings by 22.3% Recall@10, and embeddings are non-deterministic —
fatal for a stable id). So embeddings are advisory-only, never the id.

## 2. Current state (verified in the live code on `main`)

`run.BugID` (`internal/fsm/run/canonical.go:103`) is the whole identity:

```go
func BugID(issueText string) string { sum := sha1.Sum([]byte(issueText)); return hex.EncodeToString(sum[:])[:12] }
```

It hashes the **exact** issue text — **no file, no normalization**. Consequences: any rewording mints a
new id (recall failure); identical text in two different files collides to one id (precision failure);
a reformat (trailing space, case) mints a new id.

## 4. Proposed key — `(file, normalized-text)` (spec §9.8 R6; normalization is the open knob)

```go
// BugID becomes file-aware. The derivation is FROZEN once the floors (§7) are met; a change to it
// afterwards is a versioned migration (§5.2), never silent.
func BugID(file, issueText string) string {
    h := sha1.Sum([]byte(NormalizePath(file) + "\x00" + normalizeText(issueText)))
    return hex.EncodeToString(h[:])[:12]
}
```

- ✓ **File component**: reuse `judge.NormalizePath` (`diffselect.go:119`) — already the repo's
  canonical path form, used by `DiffHasFile`. A missing file (`""`) is its own bucket (see §5.1).
- **`normalizeText` — the knob you approve.** The candidates, cheapest-first, each with the recall it
  buys and the precision it risks:
  - N0 (identity — today): none. Rejected: no recall at all.
  - N1: trim + collapse internal whitespace + lowercase. Buys case/whitespace/reflow paraphrases;
    negligible precision risk.
  - N2: N1 + strip trailing punctuation + collapse runs of digits to a placeholder (so "line 42" and
    "line 51" match). Buys line-number/enumeration paraphrases; small precision risk where a number
    *is* the distinction.
  - N3: N2 + strip a leading file/line prefix the reviewers emit (e.g. `path:NN:` at the head of an
    issue). Buys "same sentence, different location prefix"; must not erase a file the finding is
    *about* (that is S-level, handled by the file component).
  - ✗ Rejected: stemming / stopword removal / token-set hashing — that is the embeddings-adjacent path
    §9.8 R6 rejects for non-determinism and cross-toolchain drift.
  - **Recommendation:** **N2**, frozen only if it clears the §7 recall floor; N1 is the fallback if N2
    trips precision on the 611-corpus. The **exact** scheme is chosen by measurement (§6/§7), not here.
- ✓ **Determinism**: pure, no timestamp/locale/embedding — stable across machines and replays (§9.8 R6).
- **Residual, named:** the "same fault, different symptom" class (a genuinely different sentence for the
  same root) is unsolvable by any content method and is **bucketed out** of the recall target (§6), not
  papered over.

## 5. The two design decisions the spec flags

### 5.1 Golden identity domain (review #35b)
`run.Golden` persists only `Comment/Severity/Category` — **no file** — while S5 keys `matched-golden`
on `BugID(golden.Comment)`. Under a file-aware key this is a domain mismatch: a golden has no file to
put in the key. Options:
- (a) **Golden inherits the matched candidate's file** — `BugID(cands[winner].File, golden.Comment)`.
  The Bug already sets `File: cands[winner].File`, so id and file agree by construction, and a matched
  golden compares in the *same* `(file, text)` domain as candidates. ✓ **Recommended** — smallest
  change, and "the golden, as matched, is about this file" is exactly what a match asserts.
- (b) Goldens carry their own file (schema change to `Golden`). More faithful if a golden is
  file-scoped by the operator, but it is an additive wire change to a persisted type and most goldens
  are authored without a file.
- (c) A separate golden-identity key space (goldens never share the candidate domain). Rejected: it
  reintroduces the "id and file disagree" split this decision exists to remove.
- ⚠ **Edge:** with (a), an *unmatched* golden (no winner) needs no id (none is minted today — S5 only
  fires on `winner >= 0`), so (a) has no unmatched-golden hole.

### 5.2 Override / continuity migration (§2.4 round-2, §3.3)
Changing the `BugID` derivation changes **every** finding id, so anything keyed on an old id breaks:
- `Unproven` clears by `Pin.Finding` — a pin emitted under the old id would never clear under the new.
- A recorded override addressing a finding by id (the `unverifiable`/process-override path) orphans.

Decision options:
- (a) **Version the derivation + migrate on read** — stamp an id-scheme version; when it changes,
  translate persisted ids forward (recompute from the retained `(file, text)`). Requires the source
  text be retained (it is — `Bug.Desc`/`Finding.IssueText` persist). ✓ **Recommended.**
- (b) One-way-door cutover (like §2.4's pins deploy): the first run under the new scheme is
  irreversible; old overrides are re-keyed once, by a migration step, and the old scheme is retired.
- ✗ Rejected: silent change (the spec's explicit prohibition — "migrated or versioned on the change,
  never silently").
- **Scope note:** this is the *FSM* finding id (`run.BugID`), distinct from reviewlog finding ids
  (`mrvf-…`). The migration concern is the FSM id space only.

## 6. The ground-truth protocol (⧗ — needs your lock before any floor can be measured)

The recall direction has no ground truth today. Proposed protocol (approve or amend):
1. **Corpus source:** the 10 persisted runs + the 611-finding precision corpus already in hand.
2. **Paraphrase set construction:** for a sampled set of confirmed findings, produce **reworded**
   variants that are the *same fault* (case, whitespace, reflow, line-number, and light lexical
   rewording — the paraphrase classes the loop actually produces across rounds), each **labeled** with
   the id-group it belongs to. Explicitly **bucket out** "same fault, different symptom" (a different
   sentence for the same root) as out-of-scope for a content key.
3. **Who authors the labels:** the ground truth is human-labeled (which variants are the same fault) —
   this is the part only you can supply/approve; the machine must not invent the labels.
4. **Pre-lock:** the set and its labels are **frozen before** any `normalizeText` variant is tuned, so
   the choice can't be fit to the test (the §5 pre-lock discipline, applied to recall).
5. **Falsifiable check:** a known-answer fixture where a correct key keeps a paraphrase group together
   and splits a distinct finding — it fails if the measurement is wrong.

## 7. The floors (⧗ — you set the numbers when the corpus is built)

Per the plan (T4.1 / §7 L3), the numeric bar is **set when the corpus is pre-locked, not invented
here**. This task freezes the algorithm **only once BOTH** hold:
- **Recall floor** on the paraphrase set (grouped-same-fault held), at a value you lock against the
  pre-locked labels.
- **Precision floor** on the 611-corpus (distinct findings never merge) — the measured baseline is 0%
  false-merge; the floor is that property held.
- **Regression guard:** a **same-text / different-file** case must produce **two** ids (the precision
  property the file component adds), and a **paraphrase** case must produce **one** (recall).

**Freeze condition:** the `normalizeText` scheme (§4) is frozen at the cheapest variant that clears the
recall floor without tripping the precision floor. Then, and only then, code lands.

## 8. Test plan (what the code half will encode, once frozen)

- **Unit (pure, deterministic):** `BugID(file, text)` — same `(file, normalized-text)` → same id;
  different file → different id; each approved paraphrase class → same id; a distinct finding → different
  id. Mutation: dropping the file component must redden the different-file test; dropping normalization
  must redden a paraphrase test.
- **Site coverage (S1–S7):** every identity-sensitive site keys on `(file, normalized-text)` — a
  same-text/different-file regression over **each** path (S2 `dedupCandidates` and S3 `dedupBugs`
  included, since a `BugID`-only change would miss the raw-text dedup). Mutation: reverting any single
  site to raw-text must redden its regression.
- **Golden domain (S5):** a matched golden and its winning candidate compare in one `(file, text)`
  domain (per §5.1(a)).
- **Migration (§5.2):** an id minted under the old scheme resolves after the scheme change (no orphaned
  override / no un-clearable `Unproven`). Mutation: dropping the migration must orphan a keyed override.
