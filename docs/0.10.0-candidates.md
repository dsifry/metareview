# 0.10.0 candidates

## Mutation testing in the review harness

**Status: TODO — deliberately out of 0.9.0.**

### Why it is worth doing

The round-7 sharded review of PR #13 (2026-08-28, 71 reviewers) produced 104 blocking
findings, 9 high. Nearly every high came from a *mutation* — delete or invert a line,
run the suite, see whether anything goes red — not from reading. Each one sat behind
100.0% statement coverage:

- `internal/fsm/export/export.go:222` — `O_NOFOLLOW` deletable, suite green: the
  symlink-attack control on the bundle write is verified by nothing.
- `internal/fsm/cli/envelope.go:55` — the `ERR_RUN_ESCALATED` row is deletable with the
  whole repo green, silently downgrading "a human must decide" to "retry automatically".
- `internal/prready/review.go:289` — `Prune`'s keep-hash replaceable with `""`, both
  packages green; a wrong hash deletes the pack set the run just wrote.
- `internal/fsm/machine/diff.go:32` — `CallRow.Index` is never assigned and ships as a
  constant `0` in the `fsm diff` envelope.
- `internal/fsm/cli/run.go:784` — the cancellation fix in `cde8d0a` has no test behind it.

Coverage reported all of this as covered. It was *executed*, not *verified*. Statement
coverage structurally cannot see: a guard that is a sub-expression of a shared boolean,
an unassigned struct field, a fixture that aliases two variables so an assertion passes
for the wrong reason, or an assertion satisfied by its own metadata.

### Why not in 0.9.0

In round 7 this was ad-hoc prompt text, hand-written per dispatch batch, and it was
added *mid-sweep*: the first 20 of 70 shards (16..27) never received the instruction.
The technique was therefore unevenly applied and is not reproducible, which also means
104 is a floor rather than a measurement.

Cost is the other half. Each mutation is a full `go test ./...` (~47s in CI) plus a
worktree copy; reviewers that mutated heavily ran 15-22 minutes each. Brute force does
not scale to every gate invocation.

### Design requirements (Dave, 2026-08-28)

1. **Incremental, not brute force.** Cache results keyed to file content hash; never
   re-mutate a file whose content has not changed. Reuse the existing `planHash` /
   `shardHash` machinery, which already does content-derived invalidation.
2. **A real operator set**, not just statement deletion: arithmetic operator
   replacement, relational/comparator swaps (`<` <-> `<=`, `==` <-> `!=`), boundary
   and constant perturbation. Deletion alone would not have surfaced the `1<<20` vs
   `1<<20 + 2` line-cap disagreement between `record.go:156` and `runchain.go:114`.
3. **Targeted selection.** Prefer newly added and newly modified guards over whole-
   package sweeps; rank candidates by "asserts a property" signals — doc comments,
   test names, spec rows.
4. **Report survivors as findings**, naming the surviving mutant, so the output is
   actionable rather than a score.
