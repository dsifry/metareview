## 1. Objective

We are **improving metareview by dogfooding it on itself.** metareview is a code-**review/gate harness**
with an **FSM-based review loop** (`metareview fsm` drives `sdlc-loop`: discover → adjudicate → fix →
verify). We are adding two capabilities to that loop, specified in an approved design spec:

- **Pins / proof-of-fix** — after the `fix` node, a deterministic **differential-test gate** proves a
  fix is actually test-guarded (a reproduction test that fails-before/passes-after the real fault —
  *preferred* — or a mutate-a-line "pin" as *fallback*), instead of taking the fix agent's word.
- **Bug.Class** — classify confirmed findings that share a *mechanism* (data-model/class bugs vs
  one-off instances) so the loop fixes the class, not just each instance.

We build this **using metareview's own review gates** (`review-task-done`, `review-epic-ready`,
`review-pr-ready`, `learn --post-merge`) and the project's TDD/DI discipline — metareview reviews the
code that improves metareview. The build follows an approved **decomposition** (epics → tasks with
DI/TDD contracts + a dependency DAG), executed **task by task in dependency order**, each proven to
meet the overall spec *and* its task-level contract *and* its tests before moving on.

## 2. Definition of Done

- **Per task:** the task's DI + TDD contract from the decomposition is built (test observed failing
  first, then implemented), **mutation-verified**, coverage gate green, and the **`metareview review
  task-done` gate returns PASS/PASS_ADVISORY with zero blockers**; then committed.
- **Per epic:** when all a task's child tasks are done, `metareview review epic-ready` passes.
- **Per PR:** `metareview review pr-ready` passes locally; then the PR is shepherded through CI +
  CodeRabbit + Cursor + the "Merge Ready (gtg)" gate to a squash-merge with **zero unresolved review
  threads**; then `metareview learn --post-merge`.
- **Overall (this handoff's scope):** **Ship 1 (Epic E1 — the differential-proof gate)** is built,
  gated, and merged, driven by the loop. The loop then continues into E2/E3/E4 **only as their
  dependencies and `⧗` spike-gates clear** (see §8) — do not build a `⧗` task past its gate.

## 4. What metareview IS (so you can navigate it)

- **A review/gate harness, not a decomposition engine.** Its commands are all gates: `review-artifact`
  (specs/plans), `review-task-done` (code chunks), `review-epic-ready`, `review-pr-ready`,
  `learn-post-merge`, and `fsm`. This repo has **no BEADS** and is **not** a metaswarm repo — it's
  developed standalone with these gates on git branches. (`docs/integrations/metaswarm.md`: metaswarm
  owns the lifecycle; metareview supplies the gates. A future goal is to absorb the metaswarm core
  workflow, but that is NOT this task.)
- **The FSM** (`internal/fsm/…`): `metareview fsm` runs a workflow (`workflows/sdlc-loop.yaml`,
  `review-loop.yaml`) as nodes — `review-lenses` (discover), `match-then-adjudicate`, `agent-edit`
  (fix), `still-present`, `cmd`. **The pins gate and the classify node we're building plug into THIS
  loop** (the `fix → prove → verify` path, and a new `classify` node before `fix`). That is the
  dogfood: we are extending the very engine that reviews our code.
- **Build discipline (non-negotiable — memory `build-process-tdd-di-coverage`):** TDD (no code lands
  without a test observed failing without it); **DI** (test-cmd runner, git access, AI judge/agent are
  injected; AI is **mock-AI** / `internal/fsm/mockai` in every test; a `mock:true` FSM row never
  satisfies a gate); **enforced ~100% coverage** via `bash tests/coverage.sh` (packages under
  `internal/fsm/…` and `workflows` must be **100%**; others must not drop below `tests/coverage-floor.txt`);
  every fix **mutation-verified** (break the line, see a *specific* test fail, restore).

## 6. Key Decisions & Rationale (do NOT undo without a stated reason)

- **`prove` is ONE differential-test gate: reproduction test PREFERRED, pin FALLBACK (§9.1).** A
  reproduction test uses the *real* fault (fail-before/pass-after); a pin uses a synthetic one. Build
  both; the reproduction execution engine (checkout pre-fix → overlay only test-only files → must FAIL
  on an *assertion* not compile error → apply fix → must PASS) is owned by T1.3 and reused by T1.5.
- **Honest claim, never "proof"/"correct":** a proven reproduction test says the *behavior* is under
  test; a proven pin says the *added line* is. Assert this per form in output.
- **`DifferentialProof` generalizes `Pin`; `ProofResult` generalizes `PinResult`.** `Kind ∈
  {reproduction, pin, deletion}`, one-of invariant, `DifferentialProof.ID` is the override key (a
  reproduction/deletion proof has `Pin == nil`, so keying on `Pin.ID` is wrong). §2.4 pin-only fields
  "read as" their generalizations; a `Pin` is the `Kind:"pin"` case.
- **Opaque test cmd (§4.2):** the consent-hashed test cmd is invoked opaquely — **whole-suite pass/fail,
  no per-test attribution, no coverage instrumentation assumed.** Any gate that needs finer signal must
  degrade or fail-closed (this bit us repeatedly in review — do not assume per-test results).
- **`Snapshot.Unproven` is Snapshot-derived and NEVER persisted** (recomputed by `Fold`). Persistence
  caps apply to `Delta.Pins`/`PinResults`/`Classes`/`FixClasses` only.
- **One-way-door deploy gate (§2.4):** the first deploy that writes the new `Delta` fields is
  irreversible (an older binary can't `Fold` that run) — record the gate; no downgrade path.
- **`classify` grouping is ADVISORY** with a recorded-reason override (§4.5) — never binding. But where
  an advisory `Remedy` label gates a *hard* enforcement (Guard-and-Go), it must **fail closed**.
- **`⧗` = a spike/decision that must clear before that task is code.** Finding-identity (T0.1) is a
  Ship-1 task, **OPEN, not de-risked**. Efficacy numbers are not claimed until the §8 isolation gap is
  resolved.

```text

 0. PICK the next ready task (in-degree 0 among not-yet-done, honoring ⧗). Ship 1 first: T1.1 → T1.2

    Reconcile: if the plan and spec disagree, the SPEC wins — fix the plan text in a follow-up, don't
    build the wrong thing.

 2. BUILD it TDD + DI first:
      a. Write the test observed FAILING WITHOUT the code (red). For a gate, write the negative/red
         case the acceptance names (e.g. "a pin that does NOT hold its line drives pins_proven red").
      b. Implement the minimum to go green. Everything injected; AI mocked (internal/fsm/mockai).
      c. MUTATION-VERIFY every gate predicate: break the exact line, re-run, confirm a SPECIFIC test
         fails, restore. A surviving mutant means a blind test — construct the distinguishing case
         (memory: surviving-mutant-means-blind-test). A claimed kill is not evidence; re-run it.

 3. GREEN the coverage gate: `bash tests/coverage.sh` — internal/fsm/* at 100%, no floor regressions.

 4. RUN THE metareview TASK-DONE GATE (this is how you prove the work meets the spec + the task
    contract + the tests):
      go run ./cmd/metareview review task-done <task-id-or-slug> --base main --evidence <evidence.md>
    Write an evidence file (suite result, coverage PASS, the mutations you killed). The gate must
    return PASS/PASS_ADVISORY with ZERO blockers (exit 0). If NEEDS_REVISION → repair and re-run with
    --previous-run <run-id>. If ESCALATED → stop; a human must narrow/split/redesign. Commit the
    review artifacts under docs/metareview/.

 5. COMMIT the task (trailer: two lines — "Co-Authored-By: <your model> <noreply@anthropic.com>" and
    the "Claude-Session: <your session url>" line). Mark the task DONE. Re-evaluate the ready set.

 6. WHEN an epic's child tasks are all DONE → run `metareview review epic-ready <epic> --base main
    --evidence …`. Before opening/pushing a PR → `metareview review pr-ready --base main --evidence …`.

 7. PR & SHEPHERD: open a PR; wait for CI + CodeRabbit + Cursor + "Merge Ready (gtg)". Triage EVERY
    bot thread (fix REAL findings — mutation-verify the fix — reply, and resolve). **Merge only when
    all checks are green AND unresolved review threads == 0** (gtg can pass STALE before a slow bot
    posts — always re-check thread count yourself). Squash-merge, delete branch, sync main.
    Then `metareview learn --post-merge <pr#> --base <pre-merge-ref>`.

 8. REPEAT with the new ready set. STOP and surface to the human at any ⧗ task (it needs a spike/
    decision, not just code) or any ESCALATED gate.
```

**Verifying "meets the overall spec AND the task/epic decomposition AND tests"** is exactly steps 1–4:
the tests encode the task contract; the task-done gate + acceptance criteria check the task against the
spec; epic-ready checks the assembled epic; pr-ready + the bots check the whole change. Don't skip a
layer — in this project each catches a different class (the bots repeatedly caught what the lenses
missed, and vice-versa).
