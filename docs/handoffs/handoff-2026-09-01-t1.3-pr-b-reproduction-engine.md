## 2. PR-B scope (spec §9.1 execution contract — authoritative)

`docs/specs/2026-08-31-pins-and-bug-class.md` §9.1 (lines ~904-911). For a `Kind:"reproduction"` proof,
`prove` must:
- **(a)** check out the **PRE-FIX** tree (`Snapshot.FixEntryHead`);
- **(b)** overlay **only the test-only files** the fix adds/changes (helpers included, **never** production
  code) from the **POST-FIX** tree (`Snapshot.Head`);
- **(c)** run the target test (the proof's `Test`) — it must **FAIL with an assertion (NOT a
  compile/import) error**. Capture order is fixed: the failing run is on the pre-fix tree with the test
  files overlaid, before any production change;
- **(d)** apply the **full fix** (the `FixEntryHead..Head` production changes, i.e. materialize `Head`);
- **(e)** re-run — it must **PASS**.

Outcome → `run.ProofResult` (reuse the four `run.PinOutcome` values): fail-before(assertion)/pass-after →
**proven**; a fail-before that is a **compile/import** error, or no fail-before → **malformed** (the
proof is bad — the honest analogue of the pin added-line/compile checks); pass-before (the test does not
actually fail on the pre-fix tree) → **survived** (a test gap, does not exercise the fault); a tree that
can't answer (missing `FixEntryHead`, checkout/worktree failure, baseline unrunnable) → **unverifiable**
(fail closed). The **compile-vs-assertion distinction is the new, load-bearing axis** (§9.2 evidence:
ablation dropped F2P 56.88%→18.84%) — `Verifier.verifyOne` has no analogue; you build the classifier.

**Not in PR-B:** the §9.2 "fails-for-the-right-reason" LLM reviewer is **T1.4**. Deletion
(`Kind:"deletion"`) verification is **T1.5** (it *reuses this engine* — design the engine so T1.5 can call
it). Keep deletion `unverifiable` (fail closed) in PR-B.

## 4. Recommended design (git strategy was maintainer-approved: real `git worktree`)

1. **A git-worktree seam** — extend `gate` (or a sibling type in `gate`/a new `internal/fsm/gitwork`)
   with `AddWorktree(ctx, sha) (dir string, err)`, `RemoveWorktree(ctx, dir)`, `CheckoutPaths`/`Apply` as
   needed, built on `gate.Exec`. Keep it a small interface so it's mockable and `kind`-injectable.
2. **A reproduction engine** (`internal/mutation/reproduction.go` or `internal/fsm/repro`) with a
   `Verifier`-style DI: given `{PreFixSHA, PostFixSHA, TestOnlyFiles, TestCmd, Dir, git, run}` → run
   steps (a)-(e) → `ProofResult`. Include the **assertion-vs-compile classifier** (parse the target
   test's failure output; a compile/import error is not a valid fail-before). Design it so T1.5's
   deletion proof can reuse the fail-before/pass-after core.
3. **A `ReproductionProver`** (analogue of `MutationProver`) that adapts the engine to a prover method.
   Extend the `Prover` interface with `ProveReproductions(ctx, proofs, spec) ([]run.ProofResult, error)`
   (or a unified `Prove`); `ProveSpec` gains `PreFixSHA`/`PostFixSHA` (from `in.Snap.FixEntryHead`/`Head`)
   and the changed-file partition. Wire both `MutationProver` + the reproduction engine at `wiring.go:263`
   using `d.Exec`.
4. **prove.go:** route reproduction proofs to the new path; on `FixEntryHead==""` or any git failure,
   `unverifiable` (fail closed). Emit the same structural marker findings (`proofFinding`) so `pins_proven`
   blocks a non-proven reproduction exactly as it does a pin.
5. **Owed-pin note:** clause (a)'s current `owesPin` triggers on an added line in the finding's own file.
   A reproduction-form fix may satisfy its finding via a committed test rather than an owned pin — check
   whether clause (a) should treat a Proven **reproduction** proof for the finding as discharging it (it
   already keys `settled` on any Proven proof of any kind, so a Proven reproduction clears it — verify
   this holds and add a test).
