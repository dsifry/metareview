## 1. Scope (spec §9.8 R7 + §2.2 widening — authoritative)

`docs/specs/2026-08-31-pins-and-bug-class.md` §9.8 R7 (lines ~1085-1090) + §2.2 (`malformed` widened,
lines ~134-172). Plan `docs/plans/2026-08-31-pins-bug-class-decomposition.md` T1.6 (lines 248-260).

A comment/whitespace/dead-code pin *compiles and breaks no test*, so the break step returns `survived`
(a blocking unproven-fix) — the wrong signal, sending the actor to "write a test for a comment." R7:
reject such a pin **before** the break step with a cheap **AST pre-screen**, classifying it
**`malformed`** (advisory for pins — clause (b) still refuses a fix that supplied only a trivial pin,
so it must be replaced) so the fix agent rewrites the pin.

**§9.3's three guards are ALREADY delivered by T1.3 PR-B** (the reproduction engine): (a) durable
committed test, (b) assertion-not-compile fail-before, (c) capture on the untouched tree first — all in
`internal/mutation/reproduction.go`'s classifier + step order. So T1.6's genuinely-new deliverable is
the **R7 pin pre-screen** only. (The plan bundles §9.3 with T1.6, but §9.3 is the reproduction form's;
the pin form's §9.3(b) analogue is the existing compile check.)

**Dead code is deferred (honest limit):** a mutation inside `if false {}` or an unused function is NOT
AST-identical, so no pure syntactic method flags it, and §9.8/§2.2 provide **no reachability contract**.
The mechanically-guaranteed R7 core is the **comment/whitespace (AST-identical) case**; implement that
and document dead-code as best-effort-or-deferred. The plan's mutation-test (a null pin must not reach
`survived`) is satisfiable with the comment/whitespace case alone.

## 2. The seams (verified against `f6dfb98`)

- **Insertion point:** `internal/mutation/verify.go` `Verifier.verifyOne` (:102-167). The decision table
  is: anchor==1 (:130) → baseline pass (:136-141) → mutate write (:144, `strings.Replace(body, From, To, 1)`)
  → compile check (:150-154) → run → `PinSurvived` (:161-164) / `PinProven` (:165). Slot the pre-screen
  after the baseline check and before the mutate/write: compute `mutated := strings.Replace(body, p.From,
  p.To, 1)` ONCE, run the pre-screen on `(body, mutated)`, and on a null result `return fail(PinMalformed,
  "…semantically null…rewrite the pin")` — then reuse `mutated` for the write at :144.
- **The pre-screen (pure, greenfield):** NO `go/ast`/`go/parser`/`go/scanner`/`go/printer` is imported
  anywhere yet. Prefer a **token-stream comparison** via `go/scanner` (simpler and fully
  position-independent, unlike printer roundtrip which can differ on blank-line preservation): scan both
  whole-file bodies with comments OFF (mode 0), collect `(tok, lit)` pairs, compare. Identical streams ⇒
  the change touched only comments/whitespace ⇒ null ⇒ malformed. If EITHER body fails to scan cleanly,
  return **not-null** (false) — a broken mutation is the compile step's job, never this pre-screen's.
- **Outcome/flow:** `PinMalformed` (`verify.go:32-47`) → `FindingsForPins` medium/advisory (:284-289) →
  `MutationProver.ProvePins` maps by value (`prove_mutation.go:39`) → `proofFinding` (`kind/prove.go:369`)
  routes a **PIN** malformed to advisory `CategoryMalformedPin` (non-blocking). Confirmed: classifying
  more PIN mutations malformed keeps them advisory (the T1.5 blocking branch is reproduction/deletion
  only) — exactly R7's intent (off the `survived` blocking path, onto advisory "rewrite the pin").
- **Fixtures:** `verify_test.go` `fixtureRepo(t, guard, test)` (:14-31) writes `calc.go` with a doc
  comment `// Allow reports whether n is within the limit.` and `func Allow(n int) bool { return <guard> }`.
  A **comment-only** null pin: `From:"// Allow reports whether n is within the limit."`, `To:"// Allow
  reports whether n is within limit."`. A **whitespace-only** null pin: `From:"return n < 10"`,
  `To:"return  n < 10"`. Control (semantic, must stay proven): `n < 10`→`n <= 10`.
