## 3. The two self-contained flags (BUILD THESE)

- **Self-served override** (`findings.Record`, `findings/findings.go:78-84`:
  `OverrideRequestedBy/…GrantedBy/…`). Fire when a **granted** record has
  `strings.EqualFold(OverrideRequestedBy, OverrideGrantedBy)` (same actor) — the residual the CLI
  cannot catch (`override.go:107-109` already refuses a *requester* who re-grants, but `GrantOverride`
  accepts an open finding with no prior request, `override.go:104`). **Discriminating negative
  (load-bearing):** a request+grant by two DISTINCT actors must NOT fire. **Mutation (plan-named):**
  collapsing the comparison to `selfServed()→true` must redden the distinct-actor negative test.
- **Whitespace/comment-only fix** (from the diff). No existing predicate — `internal/mutation`'s
  `semanticallyNull` is unexported and over two whole file bodies (wrong shape). Build a diff-based
  predicate over `judge.AddedLinesInFile`/`RemovedLinesInFile` (`internal/fsm/judge/diffselect.go:219,
  246`): a change is whitespace/comment-only when, per changed path, the added and removed lines are
  equal after collapsing whitespace and dropping comment-only lines. (Importing `internal/fsm/judge`
  into `internal/learning` is a new cross-package dep — confirm acceptable; else copy the two small
  helpers.) **Discriminating negative (load-bearing):** a substantive non-whitespace diff must NOT
  fire. **Mutation (plan-named):** stubbing `whitespaceOnly()→true` must redden the substantive-diff
  negative test.

Both flags are **advisory** learning `Candidate`s. Guard-and-Go-style over-flagging is the failure to
avoid — the negatives are the point.

## 4. DEFERRED — the R9 verbosity flag (a hidden `⧗`, maintainer decision)

§9.8 R9: "a fix materially larger than the minimal change (Guard-and-Go median 1.67×) is flagged." The
research found **no "minimal change" / expected-fix-size signal anywhere** (`gitcontext.Context`,
`findings.Record`, the `Delta` wire model, the FSM run types). The 1.67× is a *population median from
uncited literature* ("cited, not fetched — a gap"), not a per-fix baseline to divide against. The only
self-contained numeric is added÷removed lines, and mapping that onto "1.67× the minimal change" means
**choosing a proxy the spec does not define** — a load-bearing numeric-threshold decision, the same
class as T4.1's bar. **Recommendation for the maintainer:** either (i) define the proxy (e.g. flag when
added-lines ÷ max(removed-lines,1) exceeds a set ratio, or added-lines exceed an absolute threshold),
picking the value against the 1.67× median; or (ii) supply a reference/minimal-patch size in the data
model. Build verbosity once the proxy is set; it is otherwise not groundable.
