Bare fail→pass is insufficient: the pre-fix failure must be **the finding's own symptom**, not an
unrelated error. This is the reproduction-form reincarnation of the pin's own-file binding.
- The mechanical differential (fail-before/pass-after) is the **deterministic gate** (PR-B) and the
  **sole PASS path**. The symptom match is an **LLM reviewer, NOT a second gate**.
- The reviewer is **veto-only**: a mismatch raises a **blocking `NEEDS_REVISION`** finding; a match
  **adds nothing** and never produces a PASS. An LLM can veto a proof, never certify one.
- **Fail-closed (review #34):** a reviewer timeout, error, or unusable/unparseable output is itself a
  **blocking `NEEDS_REVISION`** (or a bounded retry) — never treated as approval. Mutation target: turning
  the error/parse-fail path into "approve" MUST redden a test.
- Evidence: ablating this gate dropped F2P 56.88%→18.84% (ReProAgent).

**Only reproduction proofs** are reviewed (a pin's own-file binding stays in clause (a); deletion is
T1.5). The reviewer fires **only on a `Proven` `ProofReproduction`** result.

### 3b. The reviewer judge kind (template: `still-present`)

The judge DI is `judge.Judge.Call(ctx, judge.Request) (judge.Verdict, error)` (judge.go:72-74). A new
AI-judge `Kind` needs a template const + typed input + three `case`s, mirroring `still-present`:
- template consts (system + product), `prompts.go:55, 108-120`;
- input struct (e.g. `SymptomInput{Bug run.Bug; Test, FailBefore string; ...}`), `prompts.go:174-179`;
- `RenderPrompt` case that fills + fences the slots, `prompts.go:233-243` (fenced so the audit is honest);
- `Parse` case that decodes the verdict **fail-closed** — on a parse failure the decision must be the
  BLOCKING value (see `still-present`'s `decision = kind == KindStillPresent` at prompts.go:365, and the
  missing-field default at prompts.go:397-400). For this reviewer, **parse-fail / missing field ⇒ veto
  (mismatch)**, never approve.
- add a `maxTokensFor` case (judge.go:273).

The prompt asks: *does the pre-fix failure (`FailBefore`) exhibit the finding's own reported symptom
(`Bug`)?* Verdict decision `true` = matches (no veto), `false` = mismatch (veto). Keep the **fail-closed
polarity** explicit: absence of a clear "matches" ⇒ veto.

### 3c. Where it hooks in (the `prove` node)

review — reorder so a vetoed Proven reproduction is NOT settled and DOES emit its blocking marker.
