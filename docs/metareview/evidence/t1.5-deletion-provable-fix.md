# T1.5 evidence — deletion as a first-class, provable fix (§9.4)

**Task:** T1.5 (Epic E1). Make a `Kind:"deletion"` proof provable: the `DeletionRef`↔reviewed-diff
binding, a fail-before/pass-after reproduction (reusing PR-B's engine), and a whole-suite
over-deletion scope check. Deletion previously routed to `unverifiable`.
**Spec:** §9.4 (deletion first-class/provable/encouraged), §9.1 (`Kind:"deletion"` one-of; clause (a)
own-file = `DeletionRef.File==Finding.File`), §9.6 (whole-suite before/after). **Depends-on:** T1.3
PR-B (#41), T1.4 (#42). **Base:** `main` (`002adf2`).

## What landed

A `Kind:"deletion"` proof is proven iff **all three** hold:

**(a) `DeletionRef`↔reviewed-diff binding** (`kind/prove_reproduction.go` `proveDeletion` + `spanIsRemoved`,
`judge/diffselect.go` `RemovedLinesInFile`). The fix commit's own diff (`FixEntryHead..Head`, per-file,
read via the injected `gate.Exec` git seam — **not** `in.Diff.Text`, which is the whole `BaseSHA..Head`
branch) must remove **every line of `DeletionRef.Removed`** from `DeletionRef.File`, anchored at the
fix's parent (`ParentSHA==PreFixSHA`). A free-floating/mismatched span, wrong parent, or empty span is
**malformed**. (`--no-ext-diff --no-textconv` on the read — `gate.RealExec` empties `GIT_EXTERNAL_DIFF`,
which otherwise kills a textual `git diff`.)

**(b) fail-before/pass-after reproduction** — reuses `Reproducer.Reproduce` **as-is**: the deletion is
materialized when the post-fix tree is applied (step (d) removes the deleted file). The pre-fix tree
still has the code → the test fails (assertion); the post-fix tree removed it → the test passes.

**(c) whole-suite over-deletion scope check** (`mutation.Reproducer.ScopeSuite`, NEW). Runs the **full**
consent-hashed test command (**no `-run` filter**) on both the pre-fix and post-fix trees, keyed on exit
code alone. The pre-fix suite **must be green** (a red baseline can't attribute a regression →
unverifiable); a green→green pair passes; a **green→red** transition means the deletion broke an
**existing** test (survived — the honest limit: "removing this fixed the bug and broke no existing
test", not "globally safe", §9.4).

**Routing & own-file** (`kind/prove.go`): a new `case run.ProofDeletion` enforces the own-file bind
(`DeletionRef.File==Finding.File`, malformed otherwise — the own-file guarantee that keeps the proven
code and the class gate's line the same, distinct from §9.5's `Root.File`), routes to `ProveDeletions`
(new `Prover`/`Provers` method), and the §9.2 symptom-reviewer guard is broadened to review a
deletion's reproduction test too. The former `default` unverifiable arm becomes a defensive **abort**
(all decodable kinds are now handled; an unknown kind can't occur through decode).

## Shepherding round 1 (Cursor Bugbot — real bug, fixed)

- **Cursor (High): a malformed deletion silently passed the gate.** A `Kind:"deletion"` proof that
  failed the own-file or `DeletionRef` bind was scored `PinMalformed` — ADVISORY. For a pin that is
  safe (clause (a)'s owed-pin marker is the blocking backup), but a pure deletion adds no line, so
  `owesPin` never fires and there was no backup: `pins_proven` stayed green on an unproven deletion.
  Fixed: `proofFinding` is now kind-aware — a malformed PIN stays advisory, but a malformed
  REPRODUCTION or DELETION is BLOCKING (the preferred forms ARE the fix's proof). This also closes the
  same latent hole for a pure-additive/cross-file reproduction. Mutation-verified.
