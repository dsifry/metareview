## Blocking Findings

### A1/F1: base..head marker cannot attest or track the roll-up (architecture/feasibility, HIGH — FIXED)

- Finding: the first draft made the *rendered roll-up context pack* the adjudicated lens surface, but build B's
  marker is keyed on base..head, and the roll-up (child logs, evidence file, Beads intent) lives outside the
  diff and changes independently; `review-loop.yaml` also has no seam to feed a review node a context pack.
- Resolution: the marker attests the **integration diff** (base..head — what `review-loop` actually reviews and
  `validateFromRunDiff` binds), reviewed *with the roll-up as reviewer context*; roll-up **freshness** is
  guarded by the deterministic pre-checks, which re-read current state on every `Create` invocation
  (verified: `review.go:101-117`). Split-of-concerns table added to the spec.

### C1: "epic-ready reviews only the committed span" is false (completeness/precision, HIGH — FIXED)

- Finding: `epicready.Create` folds staged+working-tree+untracked diffs unconditionally (`review.go:242`), so a
  dirty tree is reviewed but the base..head marker cannot attest it — build B's working-tree hole, re-opened.
- Resolution: spec now sets `Adversarial.WorkingTreeUnattested` when the epic tree is dirty (mirror
  `prready/review.go:203`); false claim and non-goal corrected; dirty-tree test added.

### base-asymmetry: merge-base-vs-tip default base silently wedges a correct marker (testing, HIGH — FIXED)

- Finding: `review epic-ready` with no `--base` resolves `merge-base(HEAD, main)`; the recorder with `--base
  main` resolves the tip — once main advances they differ, so a correctly-recorded marker never matches.
- Resolution: base-consistency rule added (identical explicit `--base` to gate, review-loop, and recorder);
  base-advance behavioral test added; CLAUDE.md/AGENTS.md recorder example to carry the rule.
