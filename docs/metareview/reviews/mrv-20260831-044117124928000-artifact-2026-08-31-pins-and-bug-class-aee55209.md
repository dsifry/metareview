### Blocking Findings

**B1 — The pin proof is not bound to the fix diff.** (security, feasibility, intent) The agent authors both `From` and `To`, and nothing requires `Pin.File`/`From` to lie within the commit's own diff. It can anchor to any pre-existing well-tested line, prove *that*, and leave the real change unpinned — the vacuous-`pins_proven` failure from #24 in subtler form. `classes_enumerated` checks file-in-diff for instances; pins have no equivalent. Fix: `prove` must reject any pin whose `From` anchor is absent from the commit diff.

**B2 — Pins prove line-durability, not fix-completeness; metric-1 is mis-attributed.** (intent, feasibility, testing) A valid pin proves one line is guarded; recurrence is driven by incompleteness (unfixed siblings), which pins do not touch. Metric-1 ("proven fixes stop recurring → 0") actually depends on Bug.Class, not pins. Fix: rescope what pins claim to prove and what metric-1 measures.

**B3 — The class gate checks the wrong direction and members can be silently dropped.** (security, intent, architecture) `classes_enumerated` verifies each member-file appears in the diff — satisfiable by N whitespace touches, and it runs opposite to the prose claim ("one mechanism site clears multiple members"). Worse, `FixInstance{File,Disposition,Reason}` has no back-reference to the member it answers, so a 3-member class can be "answered" by 1 FixInstance with 2 dropped and no gate detects it. Fix: `FixInstance` needs a member id; the gate must verify every member got a disposition.

**B4 — Class data has no carrier in the state model.** (architecture, completeness) §2.4 adds `Delta.Pins/PinResults/Snapshot.Unproven` but no `Delta`/`Snapshot` field for `BugClass` (classify's output) or `FixClass` (fix's output). The fold handler (`fold.go:121-152`) knows only Findings/Confirmed/Status/Commit. classify's grouping has nowhere to be stored and vanishes on replay. Blocks steps 4–6. Fix: add class carriers + fold rules.

**B5 — `Snapshot.Unproven` never clears; `Pin` has no id — convergence can't terminate.** (completeness) Nothing removes a pin from `Unproven` once proven, and `Pin{File,From,To,Test}` has no stable key, so a redone fix that changes the anchor never matches the stale entry. `Unproven` is monotonically non-decreasing → permanently drives re-discover → metric-3 (unfixed→0) unachievable. Fix: a clearing transition keyed on a stable pin/finding identity.

**B6 — Dedup/cap placement is architecturally wrong (VERIFIED in code).** (architecture) §3.0 places dedup "at the fold, before the cap" but the fold replaces findings wholesale (`fold.go:13-14`), adjudicate already exact-dedups by issue text (`dedupCandidates`, `kind.go:621`), and the cap is a hard-reject at `MaxDeltaList=256` (`kind.go:200`), not a truncate-to-100. The `findings=100` in the logs is a discover-lens cap, not the adjudicate cap the spec targets. §3.0 (owner=fold/run) and §3.3 (owner=adjudicate) also name two different owners. Fix: rework §3.0/§3.3 against the real layers; much of the exact-text dedup already exists.

**B7 — The override lifecycle is invoked but never wired, and is keyed on `finding-id` which classes/pins lack.** (security, scope, architecture) `unverifiable` (§4.1) and class dissolution (§4.5) both route through "the override lifecycle," but no build step wires it, `override request` takes a `finding-id`, a `BugClass` has no id and a `PinResult` is not a finding, and the actor can request+grant under different `--by` (CLAUDE.md: `--by` is not authentication). Advisory dissolution with an unreviewed free-text reason is an unconditional self-service escape. Touches DECISIONS 1 and 5. Fix: give machine-emitted results an override-addressable identity and require an authenticated out-of-workflow grant, or redesign these exits.

**B8 — `require_pins` coverage-detection may be uncomputable.** (scope, feasibility) "File under the test cmd's coverage" is not statically determinable for an opaque consent-hashed cmd; package-membership is the wrong predicate (package in scope ≠ line observable by a test). Collapses to self-asserted non-coverage (escape) or forcing a pin on an unobservable line (survived → livelock). Touches DECISION 2. Fix: a determinable trigger, with the residual acknowledged.

**B9 — The efficacy measurement is confounded and partly circular.** (testing) The 66% baseline is polluted by the Stop-hook + cap fixes (the loop now *finishes*), so recurrence drop can't be attributed to pins/class without a control arm; metric-2 ("sibling") is defined by the classify-under-test (instrument grades its own output) with no numeric threshold; the gold-test siblings are spread across five sequential PRs and may never co-exist in one replayable state (classify needs them together). Fix: a control arm (Stop-hook+cap on, pins/classify off), a non-circular sibling signature with a threshold, and verified co-present fixtures.

**B10 — `classify` grouping is entirely unvalidated.** (feasibility) Every §5 spike measures dedup (same-site echo removal), which the spec itself calls "the wrong tool" for classification. The set-level mechanism-grouping judgment over up to 300 findings has no spike — the central novel mechanism is shipped on reasoning, the same "takes the agent's word" failure relocated to the adjudicator. Fix: a classify spike on the labelled #24–#28 corpus before building step 6.

### Warnings

**W1 — Migration is narrow and one-directional, not a catastrophe (data-migration).** Forward reads tolerate missing keys, so the 10 existing runs stay readable IF the implementer keeps `SchemaVersion=1` and adds `Delta.Pins`/`PinResults` as additive optional fields. The one-way door: once a proved run writes pins, an older/rolled-back binary can no longer Fold it. `Finding.Source`/`Category` already exist (no-op); `Snapshot.Unproven` never persists. The spec must state the keep-v1 decision and scope which fields touch the wire.

**W2 — cap=300 is over-scope (scope).** Dedup is the required fix; 300 is "a guess guarding an unmeasured risk" the spec itself concedes it could not validate. Defer the number to the first uncapped run rather than bake it into the migration.

**W3 — The two-level intent (FSM + human/agent) is only half-served (intent).** Every mechanism and metric is FSM-scoped; the human/agent case is motivational but undesigned and never explicitly descoped.
