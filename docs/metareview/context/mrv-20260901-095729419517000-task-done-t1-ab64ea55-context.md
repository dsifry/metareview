# T1.4 evidence — the §9.2 right-reason veto-only reviewer

**Task:** T1.4 (Epic E1). The §9.2 "fails-for-the-right-reason" reviewer: an **injected AI judge** that
vetoes a *proven* reproduction whose pre-fix failure is not the finding's own symptom.
**Spec:** §9.2 (veto-only; fail-closed), §9.1 (the own-file binding migrates here for the reproduction
form). **Depends-on:** T1.3 PR-B (#41, the reproduction-execution engine). **Base:** `main` (`c7335cc`).

## What landed

**1. The pre-fix failure is surfaced** (`internal/mutation/reproduction.go`, `run/proof.go`,
`kind/prove_reproduction.go`). The reviewer's input is the assertion the target test emitted on the
**pre-fix** tree, which PR-B captured but discarded on the Proven path. `mutation.ReproResult` and
`run.ProofResult` gain `FailBefore`; the engine populates it on the Proven return; the adapter threads
it through. `run.ProofResult.FailBefore` is `json:"-"` — transient reviewer input consumed inside the
prove node, never persisted (on replay the reviewer's verdict already lives in the recorded findings).

**2. The `symptom` judge kind** (`internal/fsm/judge/prompts.go`, `judge.go`). A new `KindSymptom`
with `SystemSymptom` + `TemplateSymptom`, `SymptomInput{Bug, Test, FailOutput}`, a `RenderPrompt` case
that **fences** the untrusted symptom/test/output and cuts the failure log to its **tail**
(`CutTail`/`MaxFailOutputBytes` — the failure is at the end of a run), a `Parse` case, and a
`maxTokensFor` case. The prompt asks only the narrow question — *does THIS pre-fix failure exhibit the
finding's OWN symptom?* — not "is the finding real" (adjudicate decided that) nor "is the fix good"
(the differential decided that). **Fail-closed polarity:** `Parse` decides `false` (veto) on a JSON
error, a missing `matches` field, or an oversize verdict — a garbage reviewer never approves.

**3. The prove-node veto** (`internal/fsm/kind/prove.go`). The `prove` node runs the reviewer on every
**Proven `ProofReproduction`** result via the shared `call` helper (so the mandatory `llm_call` audit
fires). The reviewer is **veto-only**: it cannot change the deterministic result, only add a blocking
finding. On a mismatch (`Decision false`) — or, fail-closed, a reviewer error/timeout — the finding is
**not settled** and a blocking `symptomVetoMarker` (`Source: mutation-verify`, `Category:
unverifiable`) is emitted, so `pins_proven` reddens **with no gate change**. A Proven **pin** is never
reviewed (§9.2 is the reproduction form's own-file-binding migration; pins keep clause (a)). A nil
reviewer with a Proven reproduction to judge is a wiring error surfaced as
`ERR_EXECUTOR_FAILED{reason: no_reviewer}` — never a silent pass.

**4. Wiring** (`kind.Deps.Symptom`, `cli/wiring.go`). The reviewer is the run's judge (real or the
mock scenario's `*MockJudge`), so a new judge kind is testable with **zero mockai changes**.
