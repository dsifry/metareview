# T2.1 evidence — the §9.6 test-deletion gate (mutation-kill non-regression)

**Task:** T2.1. Deleting a **test** is a first-class reward-hack; a green suite afterward proves
nothing. §9.6: a test deletion is legitimate iff **mutation-kill non-regression holds** (always, the
deterministic gate) **and coverage non-regression holds where a per-line profile is obtainable** (absent
— never a block — under §4.2's opaque consent-hashed cmd).
**Spec:** §9.6, §4.2. **Depends-on:** T1.3. **Base:** `main` (`e36f60a`). **Design decision:** approved
Option 1a from `docs/handoffs/handoff-2026-09-01-t2.1-test-deletion-gate.md` (proven-pins as the
killed-mutant set, persisted via a new `Snapshot.Proven`).

## What landed

**1. `Snapshot.Proven` — the run's killed-mutant set** (`internal/fsm/run/types.go`, `fold.go`). The
fold now maintains `Proven []DifferentialProof` in temporal order, deduped by proof ID: a Proven
`PinResult` folded at the prove node appends its proof (`addProven`); `cow()`/`Clone()` clone it; it is
derived (re-folding the log reproduces it), classified `verbatim` for export. In this system a "mutant"
*is* a pin, so the set of previously-killed mutants is exactly the run's proven pins.

**2. Mutation-kill non-regression in the prove node** (`internal/fsm/kind/prove.go`
`testDeletionRegressions`). It is a **no-op unless the fix deleted a test** (`deletesATest` — a removed
`func Test.../Benchmark.../Fuzz.../Example...` line, covering both a deleted `*_test.go` and a test
removed from a surviving file). When a test is deleted, it re-verifies every previously-proven **pin**
on the current post-deletion tree via the injected `Prover.ProvePins` (the same `mutation.Verifier`); a
pin that now **survives** (the mutation still applies but the tests no longer catch it) means the
deleted test was its sole detector → a blocking `run.Finding` (`Source: mutation-verify`, `Category:
unproven-fix`) that `pins_proven` reddens on. A pin whose mutated line the fix itself **removed** is
**excluded** (`isRemovedLineInFile` — target legitimately gone, the paired code+test deletion case). A
pin that re-verifies malformed/unverifiable (its target moved/changed) is **not** a clean test-deletion
signal and is not counted.

## Design notes (build-time contracts, resolved)

- **Killed-mutant set = proven pins (Option 1a).** No mutation-corpus generator exists and none is
  added; §9.6's "reuses the pins' engine" is realized by re-verifying the run's proven pins.
- **Mutant identity / the collision concern is N/A under Option 1a.** The spec's `(File, span)`-collides
  worry applies to a *generated corpus*; a proven pin is identified by `DifferentialProof.ID` (=
  `PinID(finding, file, from, to)`), and `mutation.Verifier` requires a pin's `From` to match **exactly
  once** in its file — so two distinct proven pins cannot collide on `(file, from)`. The plan's
  "collapse the id to `(File, span)`" mutation-test targets Option 2's corpus id, which this design does
  not build.
- **Coverage non-regression → mutation-only under the opaque cmd.** §4.2/§9.6 state the opaque
  consent-hashed `go test ./...` yields **no** per-line coverage signal (a single all-or-nothing
  invocation), so coverage is recorded **unavailable** and mutation-kill gates alone — exactly the
  plan's third acceptance criterion ("degrades to mutation-only under an opaque cmd"). The coverage
  before/after line-diff for a workflow that *does* expose a per-line profile is a scoped extension
  (§9.6 layer 1); no current workflow exercises it.
- **Reproduction/deletion proofs are out of §9.6's mutation-kill scope** (which is pins). A committed
  reproduction test's durability is the §9.3(a) guard already in the reproduction engine.
