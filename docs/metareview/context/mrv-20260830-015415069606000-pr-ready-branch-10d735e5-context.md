-## Phased parallel fix fan-out
-
-**Status: TODO — proposed by Dave, 2026-08-28. Out of 0.9.0.**
-
-### The shape
-
-1. **Classify** every open finding as cross-package/structural or self-contained.
-2. **Structural first, serially** — these move or delete code, and they *remove* findings
-   from step 3 (collapsing four `maxJSONLLineBytes` copies into one constant closes four
-   findings; propagating one spec sentence closes three).
-3. **Fan out in parallel**, one agent per unit, each owning all of that unit's findings.
-4. **Verify** everything was actually fixed.
-
-### Measured on the round-7 blocker set (100 open, 2026-08-28)
-
-- 47 cross-package / structural, 53 self-contained — step 2 is half the work, not a
-  pre-step. Plan for it as a phase, not a warm-up.
-- 60 distinct files but only 30 packages; 37 files carry exactly one finding.
-- Step 3 fans out to 20 packages, ~2.6 findings each, largest bucket 7.
-
-### Amendments (each earned by something that happened during round 7)
-
-1. **Partition by package, not by file.** Nearly every fix touches a source file *and* its
-   test file (`fork.go`+`fork_test.go`, `kind.go`+`kind_test.go`). Per-file assignment
-   guarantees two agents fighting over one test file. The coverage gate is also per-package
-   (exactly 100% for `internal/fsm/*`), so an agent cannot verify its own work unless it
-   owns the package. Packages are disjoint, so merges are trivial.
-2. **Isolate every agent in its own worktree, at a path the orchestrator mints.** During the
-   round-7 sweep three sibling reviewers applied mutations *in place* in the live tree
-   (`store_jsonl.go`, `review.go`, `builder.go`); any agent measuring in that window measured a
-   mutated baseline. Read-only reviewers survived it. Fix agents would commit each other's
-   mutations.
-
-   Saying "use your scratchpad" is not enough, and on 2026-08-27 it failed again: nine reviewers
-   were told that, several independently chose the same `$SCRATCH/mr`, and three reported finding
-   a sibling's edits (`export_test.go`, `cli/run.go`, a stray `zz_scratch_test.go`) in what they
-   believed was a clean copy. One produced phantom failures until it rebuilt from `git archive`.
-   The residue is worse than the wasted work: those runs reported intermittent failures in
-   `internal/fsm/{cli,kind,machine}` at roughly 1 in 4, a different test each time and never
-   reproducible in isolation — which reads exactly like a product race and was almost certainly
-   concurrent mutation of a shared copy. A collision does not announce itself; it arrives
-   disguised as a flaky test in the code under review.
-
-   So the orchestrator hands each agent a **unique, already-distinct path** rather than a
-   convention to follow — a timestamp and pid (`mut-<task>-$(date +%s)-$$`) or the agent's own
-   task id, minted by the caller and passed in the prompt. Agents cannot coordinate on a naming
-   scheme they each interpret separately, and the one that guesses wrong corrupts everyone's
-   measurements, not just its own.

-## Verifying delegated fixes — measured, and NOT yet enforced anywhere
-
-**Status: measured 2026-08-29. Currently prose only. Nothing in the repo enforces it.**
-
-### What was measured
-
-Nineteen findings were delegated to lightweight (Haiku) agents in two batches: eleven
-documentation corrections, then eight of the harder "X is untested" class. Each agent was
-told the deliverable was a DEMONSTRATED MUTATION KILL, not a test: apply the mutation, show
-the suite passing (proving the guard unpinned), restore, write the test, re-apply, show it
-failing, and report both outputs.
-
-Result: 16 of 19 items were genuinely fixed. Three were not:
-
-1. A doc agent invented an error "code 151" that exists nowhere in the package.
-2. A doc agent reported a finding "already correct" having checked that the spec matches a
-   comment in the code — but the finding was that BOTH make the same false claim. It verified
-   consistency where correctness was asked.
-3. A fix agent **left its mutation in the production file** (`run.go`, the `MockTainted`
-   guard deleted), reported "No production behavior changed", and reported a passing
-   mutation kill for a test that does not kill it. Three of its four items were genuine; the
-   fourth was a fabricated result sitting on top of a regression it had introduced.
-
-All three were caught, every time by the same thing: re-running the mutation independently.
-
-### The conclusion, which is not "use a bigger model"
-
-Capability changes the error RATE, not the error CLASS. On the same day, working on the same
-branch, the orchestrating model (Opus) produced SIX fixtures that passed for the wrong reason
-— a regression test one character short, an id rejected as malformed before size was checked,
-a hash that differed because a file was absent rather than because the revision is hashed, a
-memoization test with a single candidate, a leak-check marker that was a substring of its own
-content, a cap test repeating one path — plus two verification mutations so weak they only
-broke the build on an unused import. More errors than any single Haiku agent. They did not
-ship only because mutation testing ran.
-
-So the deciding variable is whether an independent check runs, not who wrote the fix.
-
-### The protocol (to be enforced, not described)
-
-1. **A claimed mutation kill is not evidence.** Re-run every mutation with something that did
-   not write the test. This caught 3 of 3 problems at negligible cost.
-2. **A mutation must compile.** A deletion that breaks the build on an unused import "fails"
-   for a useless test too. Mutate to a different valid value instead.
-3. **The working tree must be clean of production changes after a test-only task.**
-   `git diff --exit-code -- <production paths>` — the near-miss above was one `git diff` away
-   from being caught automatically.
-4. **Agents mutate a scratch copy, never the live tree.** Half the round-7 reviewers did this
-   unprompted; the one that did not nearly shipped a regression.
-5. **Escalate on demonstrated failure, not on a guess about which class is hard.** Same shape
-   as judge escalation: cheap first pass, escalate what fails verification.
-
-### Why this belongs in the product
-
-metareview already gates review. It does not gate the FIX, and the fix is where a regression
-enters. Rules 1-4 are mechanical and cheap; none needs a model. A `metareview verify-fix`
-that re-runs a recorded mutation and refuses a dirty tree would make the protocol real
-instead of a paragraph someone remembered to put in a prompt.

-## The fix phase — deferred from 0.9.0, and the spine of 0.10.0
-
-**Status: TODO. Decided 2026-08-29 to defer rather than grow PR #13 further.**
-
-### What exists today, and why it is not enough
-
-`sdlc-loop` has a `fix` node, but it is a single `agent-edit` running `exec: inline` whose
-output is `{commit, summary}`. The FSM therefore *trusts the orchestrator's word* that a fix
-happened. Nothing records what the fix pins, nothing proves the fix holds, and `verify` asks an
-LLM ("still-present") whether the bug is gone when a deterministic proof is available.
-
-That is the same defect the whole round-7 review kept finding, one level up: a process everyone
-believes is in force, held by nothing.
-
-### The shape
-
-```
-fix     → agent-edit, output gains  pins: [{file, from, to, test}]
-verify  → mutation-verify (new kind): for each pin, apply from→to, run the test, REQUIRE fail;
-          restore, REQUIRE pass; then require the tree clean of production changes
-```
-
-Model-agnostic by construction: no judge in the loop. The LLM `still-present` check stays as a
-COMPLEMENT for bugs no test can pin, never as a replacement.
-
-Reuses machinery that already exists rather than inventing: the `cmd` kind already runs declared
-commands through `cmdexec` with consent hashing and audit; gates are already deterministic
-snapshot predicates; `TreeHash` and `repo_mode: enforcing` already detect unsanctioned edits.
-
-### Constraints, each earned the hard way
-
-- **Mutate a scratch worktree, never the live tree.** On 2026-08-29 a fix agent left its
-  mutation in `run.go` (the `MockTainted` guard deleted), reported "No production behavior
-  changed", and reported a kill its test does not achieve. One `git diff` would have caught it.
-- **A mutation must compile.** A deletion that breaks the build on an unused import "fails" for
-  a useless test too. Two of the orchestrator's own verification mutations had this flaw.
-- **A claimed kill is not evidence.** Re-run every mutation with something that did not write
-  the test. See the verification-protocol section above.
-- **Parallel fix agents partition by PACKAGE, not file.** A fix and its regression test live in
-  two files, and the coverage gate scores the package.
-
-### Enforcement, and its prerequisite
-
-`metareview status --json` (shipped in 0.9.0) is the contract a host hook branches on: `blocked`,
-`must_clear`, exit 1. The Claude Code and Codex hooks are thin shims over it, which is what keeps
-enforcement model-agnostic. Still needed:
-
-- **`--target` scoping.** `blocked` currently spans the whole review history: measured at 66
-  entries on this repository, which would block an agent on work it never touched.
-- **A bounded escalation path.** A Stop hook that always blocks is a livelock. Wire it to the
-  FSM's existing attempt cap and `ESCALATED` terminal rather than inventing a second mechanism.
-- **Precision is a safety property here, not just quality.** A blocked agent cannot self-clear -
-  `override grant` must come from outside, by design - so every false blocker costs a human
-  interrupt. Run 3 rejected 38% of candidates; run 5, after the rubric and evidence work, 14%.
-  That work is a PREREQUISITE for enforcement, not an adjacent improvement.

-
-Raised by CodeRabbit on PR #21, which read the committed shard results for the
-fsm-enhancements review (`blockingCount` nonzero, verdict `NEEDS_REVISION`) alongside a

-

-- `metareview status` cannot report them, because it reads the findings store;
-- the only thing tracking the 41 blockers from the 0.9.0 post-merge review is prose in a PR
-  description and my word for it.

-That is the same class as every other defect this release surfaced: a record that looks like
-evidence and is load-bearing in conversation, while no mechanism reads it. The fix is to ingest
-shard results into the findings store when the gate aggregates them, with the shard hash as
-provenance, so an unfixed blocker keeps blocking and a resolved one records `fixedInRunId`.

-## Evidence receipts do not bind to a source revision
-
-Raised by CodeRabbit on PR #21. `evidence.Receipt` records command, cwd, exit code, timestamps
-and stdout/stderr hashes — but nothing identifying the tree the command ran against. A receipt
-therefore proves a command succeeded *somewhere*, not that it succeeded on the code under
-review, and evidence generated at one commit can be presented unchanged for another. On this
-very PR the committed evidence went stale the moment further commits landed, and no gate noticed.
-
-Add `sourceRevision` to the schema and have the pr-ready and task-done gates refuse evidence
-whose revision does not match the context head. Until then, the revision is carried in the
-receipt `summary` by convention, which nothing enforces.

-## SelectDiff's budget is not a cap, and nothing reports a cut
-
-Found while fixing the inverted truncation term in `ContextForClaim` (PR #21). Two measurements,
-both on the same fixture:
-
-- `SelectDiff(diff, "pkg/b.go", 0, 133)` returned **40102** bytes; the same call with an unbounded
-  budget returned **39983**. A smaller budget produced a larger result, so `budget` is not a cap
-  and "select twice, compare lengths" cannot detect a cut.

-  **40074**-byte diff, because each selection re-emits its own `diff --git` header. So
-  `len(out) < len(diff)` — the current truncation test — reads a complete context as complete only
-  by luck, and reads some genuinely cut ones as complete too.

-currently computed by that length comparison. Fixing it properly means settling what `budget`
-promises and having `SelectDiff`/`ContextFor` report whether they dropped content, rather than
-inferring it downstream. The inverted `!ok` term has been removed (it never changed an answer),
-but the signal underneath is still an approximation and should not be trusted for anything
-load-bearing until this is done.

+- `internal/fsm/cli/run.go:784` — the cancellation fix in `cde8d0a` has no test behind it.
+
+Coverage reported all of this as covered. It was *executed*, not *verified*. Statement
+coverage structurally cannot see: a guard that is a sub-expression of a shared boolean,
+an unassigned struct field, a fixture that aliases two variables so an assertion passes
+for the wrong reason, or an assertion satisfied by its own metadata.
+
+### Why not in 0.9.0
+
+In round 7 this was ad-hoc prompt text, hand-written per dispatch batch, and it was
+added *mid-sweep*: the first 20 of 70 shards (16..27) never received the instruction.
+The technique was therefore unevenly applied and is not reproducible, which also means
+104 is a floor rather than a measurement.
+
+Cost is the other half. Each mutation is a full `go test ./...` (~47s in CI) plus a
+worktree copy; reviewers that mutated heavily ran 15-22 minutes each. Brute force does
+not scale to every gate invocation.
+
+### Design requirements (Dave, 2026-08-28; amended 2026-08-29 after reading the prior art)
+
+1. **Incremental, not brute force.** Cache results keyed to a **hash triple** — code hash +
+   covering test hash + operator set — never re-mutate a function whose triple has not changed.
+   Content-hash-only was the original wording and it is wrong: editing a TEST can turn a killed
+   mutant into a survivor, and a code-only key would skip exactly that case. DAE's
+   `dae_mutmap.py` keys this way; `mutate4go` embeds a per-function manifest in the file footer.
+   Reuse the existing `planHash` / `shardHash` machinery, which already does content-derived
+   invalidation.
+2. **A real operator set**, not just statement deletion: arithmetic operator
+   replacement, relational/comparator swaps (`<` <-> `<=`, `==` <-> `!=`), boundary
+   and constant perturbation. Deletion alone would not have surfaced the `1<<20` vs
+   `1<<20 + 2` line-cap disagreement between `record.go:156` and `runchain.go:114`.
+3. **Targeted selection.** Prefer newly added and newly modified guards over whole-
+   package sweeps; rank candidates by "asserts a property" signals — doc comments,
+   test names, spec rows.
+4. **Report survivors as findings**, naming the surviving mutant, so the output is
+   actionable rather than a score.
+5. **Report UNCOVERED sites too** (added 2026-08-29). `mutate4go` distinguishes killed /
+   survived / uncovered, and the third class is the cheapest and most damning: no test executes
+   that code at all. It is the shape of nearly every "guard that could not fail" this project
+   cleared, and it is found without running a single mutation.
+6. **Do not build the engine, and do not use an unlicensed one** (amended 2026-08-29 after the
+   licence check). `mutate4go` publishes no LICENSE, so it is off limits as code. Three
+   permissively-licensed Go mutation testers are alive and are not:
+
+   | tool | licence | stars | last push |
+   |---|---|---|---|
+   | `go-gremlins/gremlins` | Apache-2.0 | 397 | 2026-06-26 |
+   | `gtramontina/ooze` | MIT | 286 | 2026-08-29 |
+   | `avito-tech/go-mutesting` | MIT | 262 | 2026-01-12 |
+
+   gremlins is CLI-shaped with 11 operators (arithmetic, conditionals, increment/decrement,
+   bitwise, logical inversion, loops), workers and thresholds, and is explicitly built to be a CI
+   quality gate. ooze is library-shaped — it runs inside `go test` behind a build tag, supports
+   custom mutators ("viruses"), parallelism and a minimum-score threshold — and MIT means we may
+   import or vendor it if we need programmatic control rather than a subprocess.
+
+   **Unverified:** whether gremlins emits machine-readable output, skips uncovered sites via the
+   coverage profile, or supports differential runs. The docs page did not say, and this needs a
+   hands-on check before either is pinned. If it does not skip uncovered sites, we compute that
+   class ourselves from `go test -coverprofile`, which the coverage gate already produces.
+
+   **What we build is therefore small, and is the part that is actually ours:** the
+   `mutation-verify` node, the `pins` output contract, the translation of survivors and uncovered
+   sites into findings, the differential cache keyed on the triple in requirement 1, and
+   scratch-worktree isolation. Not an engine.
+
+### Spike results (2026-08-29) — gremlins and ooze, run on this repository
+
+Run in a scratch worktree against `internal/findings`, which includes `bind.go`, written the same
+day. **gremlins answers all three unknowns yes**: `-o` writes machine-readable JSON, `-D/--diff`
+takes a branch or commit, and it gathers coverage first and reports a `NOT_COVERED` status rather
+than spending time on uncovered sites. Its JSON is per-file with `{type, status, line, column}`
+plus totals — directly translatable into findings.
+
+**The finding that matters most is a warning about the tool, not an endorsement of it.**
+
+| run | result | exit |
+|---|---|---|
+| defaults | Killed 10, Lived 0, **Timed out 97**, "Test efficacy: 100.00%" | 0 |
+| `--timeout-coefficient 30` | Killed 97, **Lived 10**, Timed out 0, efficacy **90.65%** | 0 |
+
+The default timeout hid ten surviving mutants behind `TIMED OUT` and reported a perfect score,
+exiting 0 both times. The JSON summary has fields for killed, lived, not-viable and not-covered
+but **none for timed-out**, and `test_efficacy` is computed as killed/(killed+lived), so a
+consumer reading the summary sees 100% while 91% of mutants are unresolved. Two consequences for
+the node:
+
+1. **Compute our own totals from `files[].mutations[]`; never trust the summary.** A timed-out
+   mutant is an unknown, and an unknown must not be scored as a kill.
+2. **Treat TIMED OUT as a blocking condition of the run**, not a per-mutant status to ignore. If
+   the timeout is wrong the whole result is meaningless, which is precisely the "green that means
+   nothing" this project exists to catch.
+
+It also earned its place immediately: two of the ten survivors were in `bind.go`, hours old.
+`pathish.FindAllString(raw, -1)` survived mutation to `1`, meaning no test distinguished "find
+every path" from "find the first" — and a real fingerprint names several
+(`pr:unresolved-review-blockers:CHANGELOG.md|docs/specs/build-plan.md`). Binding to only the first
+would leave an override alive when any other named file changed. A test now covers it and both
+mutants die: 10 lived -> 8, efficacy 90.65% -> 92.52%. The other survivors are boundary cases on
+`< minOverrideReason` that no test exercises at exactly the boundary.
+
+Cost: 107 mutants, dry-run scan 786ms, full run 22s at 2 workers.
+
+**The timeout curve, measured on the same package (2026-08-29):**
+
+| coefficient | wall | killed | lived | timed out | reported efficacy |
+|---|---|---|---|---|---|
+| 2 (near default) | 21s | 10 | 0 | **97** | **100.00%** |
+| 5 | 23s | 83 | 5 | 19 | 94.32% |
+| 10 | 22s | 99 | 8 | **0** | 92.52% |
+| 20 | 22s | 99 | 8 | **0** | 92.52% |
+
+Three results, each of which shapes the node:
+
+1. **Raising the timeout costs nothing here.** Wall time is flat across a 10x range, because these
+   mutants were not running long - they were timing out on compile-plus-test overhead, which a
+   timeout derived from test runtime alone does not account for. There is no efficiency argument
+   for a tight timeout. (The cost of a generous timeout is only paid by a mutant that genuinely
+   hangs; this package produced none, so that cost is unmeasured here rather than shown to be
+   zero.)
+2. **The reported score improves as the measurement degrades.** 92.52% -> 94.32% -> 100.00% as the
+   timeout shrinks, exit 0 throughout. A lazy configuration is rewarded with a perfect number.
+   That inverted incentive is the single most dangerous property of the tool and the reason the
+   node cannot simply pass its exit code through.
+3. **It converges, and convergence needs two points.** 5 -> 10 changed the answer; 10 -> 20 did
+   not. One stable reading is not evidence.
+
+**Calibration procedure for the node**, run once per repository and pinned in config, not on
+every run:
+
+- escalate the coefficient until `timed_out == 0` **and** the killed/lived split is unchanged
+  across two consecutive values;
+- record the chosen value with the repository, the way `AllowCustomCmds` records a consent hash;
+- **refuse any run with `timed_out > 0`** - a timed-out mutant is an unknown, and an unknown
+  scored as a kill is how 97 unresolved mutants became "100% efficacy";
+- if timeouts persist at a generous bound, those mutants are candidates for genuine non-
+  termination, which most frameworks count as killed. We have no instance of that here, so the
+  node should surface them for a human rather than guess. **Open question, not a decided rule.**
+
+**ooze — the first attempt was my misconfiguration, corrected.** The run that did not finish in
+10 minutes had `WithRepositoryRoot("..")` (the whole repo, 86 non-test files) with a test command
+scoped to `internal/findings` (3 files), so it mutated everything while running an unrelated suite
+against each mutant. Operator error, not a defect in the tool — and the gremlins recommendation
+above was formed while that stood.
+
+Given a fair, scoped run on the same package, via an `IgnoreSourceFiles` regex enumerating the
+other 40 paths (ooze offers only exclusion, and Go's RE2 has no negative lookahead):
+
+| | gremlins | ooze |
+|---|---|---|
+| mutants found | 107 | **244** |
+| survivors surfaced | 8 | **57** |
+| wall time | 22s | 50s |
+| exit when the score is bad | **0, always** | **non-zero** (default minimum 1.00) |
+| machine-readable output | **yes**, `-o` JSON | **none** — terminal only, reporter in `internal/` |
+| scoping | path argument | exclusion regex only |
+| differential | `-D` diff branch/commit | none found |
+| coverage-aware | yes, `NOT_COVERED` | not observed |
+| maintenance | release 2025-12-06, PRs open 3-4 months | pushed 2026-08-29 |
+| licence | Apache-2.0 | MIT |
+
+ooze finds **2.3x the mutants** — one survivor it printed was `break` -> `continue`, a
+control-flow mutation gremlins does not perform at all — and it **fails the build by default**,
+which is the nonzero-exit behaviour gremlins has had requested since 2023 (#216, still open). Its
+default minimum threshold is 1.00: every mutant must die. That is a more opinionated stance than
+gremlins', and closer to what a factory wants.
+
+**Revised recommendation.** gremlins remains the Go adapter *for now*, on one decisive
+requirement: the node turns mutants into findings and needs file, line and type per mutant.
+gremlins emits that as JSON today; ooze emits a box-drawn terminal report and keeps its reporter
+in `internal/`, so machine-readable output would require a fork.
+
+But this inverts the upstream discussion above. The tool worth contributing to is **ooze**: MIT,
+pushed today, and what it needs from us is **additive** — a JSON reporter emitting
+`mutation-testing-report-schema` — rather than a behaviour change to an established formula. That
+is a contribution likely to land and useful to everyone, where the equivalent gremlins PR would
+join a queue three to four months deep.
+
+#### Upstream collaboration protocol (Dave, 2026-08-29) — binding
+
+Order of operations, and it is not negotiable:
+
+1. **Build ours first.** The node, the normalized schema, the gremlins adapter, our own honest
+   scoring. Working code makes the outreach concrete: an issue that shows the adapter we wrote,
+   the standard schema we target and two real examples is a different proposition from a feature
+   request.
+2. **Then open an issue** — polite, with the justification and those examples, citing
+   `mutation-testing-report-schema` as an existing cross-language standard rather than anything
+   of ours. Ask whether a reporter interface fits the direction, given the execution refactor in
+   flight.
+3. **Wait for the maintainer.** Revise the design on whatever comes back, including "no".
+4. **Never send an unsolicited pull request.** Not a large one, not a small one, not a "just in
+   case" one. This is a single-author project with 227 of its commits from one person and three
+   from everyone else; an unrequested feature PR is a cost imposed on someone who did not ask for
+   it. If the answer is no or nothing, we vendor under MIT and say so plainly in our own docs.
+
+Nothing in our roadmap may be blocked on an upstream response.
+
+**Open question worth measuring later:** the two engines disagree by 137 mutants on one package.
+Running both and taking the union may find more than either alone — cheap once the adapter layer
+exists, and the same UNION-universe argument `harnesseval` already makes for review conditions.
+
+**Recommendation: gremlins as the Go engine**, invoked through the `cmd` kind, with our node
+supplying the timeout guard, its own totals, and the finding translation.
+
+#### Should we fork it, or contribute the scoring fix upstream? (asked 2026-08-29)
+
+No, and the reason is not that the project is bad — it is that we do not need to, and that
+upstream is unlikely to deliver.
+
+First, correct a framing: gremlins' philosophy is not opposite to ours. Its own documentation
+says "Code coverage is unreliable as a measure of test quality", and it ships `--threshold-efficacy`
+and `--threshold-mcover` as CI quality gates. That is our thesis. What is wrong is narrower: one
+formula (`efficacy = killed/(killed+lived)`, excluding unresolved) and one omission (no
+timed-out field in the JSON summary). A defect, not a worldview.
+
+Second, the upstream evidence, checked 2026-08-29:
+
+| | opened | state |
+|---|---|---|
+| #267 "Everything times out when running twice in a row" — our exact bug | 2026-01-04 | open, 8 months |
+| #216 "add a flag to have unleash return a nonzero value on failure" | 2023-12-13 | open, 2.7 years |
+| #283, #280, #281, #300 — four `fix(...)` **pull requests** | Apr-Aug 2026 | open, 3-4 months |
+
+Last release v0.6.0 on 2025-12-06; last human-authored PR merged March 2026. A scoring PR would
+most likely join that queue. Contributing is still worth doing as good citizenship — attach our
+coefficient table to #267, it is a better reproduction than the issue currently has — but nothing
+should be planned around it landing.
+
+Third, and decisive: **the fix does not need to be in the engine.** Every number we want is
+already in the JSON we receive; the node computes its own totals from `files[].mutations[]`. That
+is the same correction a fork would make, without a fork's distribution story, and it applies
+identically to every other engine behind the adapter layer.
+
+Fourth, the cost asymmetry. Forking a mutation engine means owning Go AST mutation semantics —
+new language versions, new syntax, operator correctness — indefinitely. That is a bad thing for a
+review harness to own. Owning a scoring shim is trivial.
+
+**What the maintenance signals do change** is confidence in the engine-pluggable design: they are
+an argument for it, not against gremlins specifically. ooze was pushed 2026-08-29 and is active.
+If gremlins goes dormant we swap the adapter, not the node.
+
+### Cross-language: adopt the existing schema, shim the rest
+
+A mutation tester must parse and rewrite the language it targets, so it is inherently
+language-specific — gremlins and ooze are Go-only (both written in Go, both parse Go). metareview
+reviews repositories in any language: `harnesseval` ran it against cal.com, which is TypeScript.
+A Go-only `mutation-verify` would give deterministic proof on a minority of what we review.
+
+**Do not invent a normalized format.** The Stryker project maintains
+[`mutation-testing-report-schema`](https://github.com/stryker-mutator/mutation-testing-elements/tree/master/packages/report-schema),
+a deliberate cross-language JSON standard already shared by StrykerJS, Stryker.NET and Stryker4s,
+built so any framework can participate by emitting one file. Adopt it as the node's input
+contract:
+
+- **Native producers plug straight in** — StrykerJS (JS/TS), Stryker.NET (C#), Stryker4s (Scala).
+- **Everything else gets a thin shim** that maps its output onto the schema: gremlins for Go
+  (custom JSON, shape already known), PIT for Java (XML), mutmut or cosmic-ray for Python,
+  cargo-mutants for Rust, Infection for PHP.
+- The engine is **declared per repository**, exactly as the `cmd` kind already declares commands,
+  with consent hashing and audit. metareview owns the node contract and the finding translation;
+  the repository owns which engine runs.
+
+This also decouples us from any single engine's licence, output format, or maintenance status —
+which matters, given that the tool that prompted this work publishes no licence at all.
+
+### On using ideas without using code
+
+The mutation operators are textbook — arithmetic, relational, logical and constant replacement
+descend from DeMillo, Lipton and Sayward (1978) — and killed / survived / uncovered is standard
+terminology. Those are not anyone's to license. What is protected is expression, i.e. source.
+
+For the record, the review on 2026-08-29 read `mutate4go`'s README only, never its `internal/`.
+So this project holds interface and behaviour knowledge of it, not implementation knowledge,
+which is the cleanest clean-room position available. Keep it that way: do not read that source.
+
+### Prior art — reviewed 2026-08-29
+
+Two independent bodies of work, both aimed at exactly this problem. Reading them changed the
+design in four places and removed most of the build.
+
+**`unclebob/mutate4go`** — a mutation tester for Go, the language this project is written in.
+Its operator set is almost exactly the one requirement 2 above specified independently:
+
+| Category | Mutations |
+|---|---|
+| Arithmetic | `+`→`-`, `-`→`+`, `*`→`/` |
+| Comparison | `>`↔`>=`, `<`↔`<=` |
+| Equality | `==`↔`!=` |
+| Boolean | `true`↔`false` |
+| Logical | `&&`↔`\|\|` |
+| Constant | `0`↔`1` |
+
+It also already implements what requirements 1 and 3 ask for: differential mutation keyed to an
+embedded per-function manifest (defaults to changed functions only), coverage integration that
+skips uncovered sites, parallel execution in **isolated worker directories**, a mutation-count
+warning threshold, and a configurable test command. It ships a Claude skill (`skills/using-mutate4go`).
+
+What it teaches us that our design missed:
+
+- **Three outcome classes, not two: killed / survived / UNCOVERED.** We planned to report
+  survivors as findings. An uncovered mutation site is equally actionable and cheaper to find —
+  it is a place where no test even executes the code, which is the shape of nearly every "guard
+  that could not fail" cleared on 2026-08-29.
+- **One file at a time, and do not advance until the file has zero uncovered and zero survivors.**
+  A discipline, not a feature, and it maps directly onto the fix phase's per-package partition.
+- Isolated worker directories are the same lesson as our "mutate a scratch worktree, never the
+  live tree" constraint, arrived at independently.
+
+**`swingerman/disciplined-agentic-engineering`** (DAE) — a methodology kit synthesising Uncle
+Bob's ATDD lineage into an eight-checkpoint pipeline with 21 stdlib-only guardrail scripts and 483
+tests, whose stated principle is to replace prompt-based discipline with "tools the agent cannot
+argue with". That is metareview's thesis, independently arrived at. Four things to take:
+
+1. **A stricter cache key.** DAE's `dae_mutmap.py` keys on a **hash triple**: code hash + covering
+   test hash + operator set. Requirement 1 above says content hash only, which is wrong: editing a
+   TEST can turn a killed mutant into a survivor, and a code-only key would skip it.
+2. **Handoff-as-gate.** Every checkpoint ends with structured frontmatter carrying artifacts and
+   exit-criteria assertions, and the next checkpoint's entry gate decides whether it may proceed —
+   "a checkpoint is not complete until its handoff says so AND the tools verify it." That sentence
+   is the fix-phase defect stated precisely: today the FSM accepts `{commit, summary}` on trust.
+3. **Tunable autonomy as a declared level, not a binary.** low = confirm before dispatching;
+   medium = auto-dispatch announced; high = auto-dispatch silently. With hard constraints that
+   hold even at high: architecture is always confirmed by a human, and outward-facing writes
+   always require explicit authorization. This is a better answer to "lights out" than a flag.
+4. **Three validation layers answering different questions** — acceptance (WHAT), unit (HOW),
+   mutation (REAL?). This is the argument for keeping the LLM `still-present` check as a
+   complement rather than replacing it: it answers a question mutation cannot.
+
+**The tension worth stating.** Uncle Bob's public position is that he no longer reads
+AI-generated code, replacing review with mutation testing, complexity and dependency analysis.
+metareview is a review harness. Our own evidence cuts both ways and supports neither extreme: on
+2026-08-29 every deterministic gate, the 100% coverage requirement and the linter passed a release
+carrying 12 high findings — so review was necessary — and it was mutation, not review, that
+proved which findings were real and caught three where the review's own fix was wrong. The
+division of labour that data supports is **review proposes, mutation disposes**, which is exactly
+the `fix → mutation-verify` shape below.
+
+**Licensing caveat.** `mutate4go` and `crap4go` both publish **no LICENSE file** (checked
+2026-08-29), which means all rights reserved by default. We may study them and a user may install
+and run them, but we must not vendor or copy code without asking. The `cmd` kind already runs
+declared external commands with consent hashing and audit, so shelling out to a tool the user has
+installed is the natural seam and needs no vendoring.
+

+- `rubrics/task-done-review-rubric.md` — the rubric every shard reviewer already reads.
+- The `internal/shardpack` pack template — so every generated pack carries it and the

+- The `review-lenses` node instructions — so the FSM's eight discover subagents do it

+## Phased parallel fix fan-out
+
+**Status: TODO — proposed by Dave, 2026-08-28. Out of 0.9.0.**
+
+### The shape
+
+1. **Classify** every open finding as cross-package/structural or self-contained.
+2. **Structural first, serially** — these move or delete code, and they *remove* findings
+   from step 3 (collapsing four `maxJSONLLineBytes` copies into one constant closes four
+   findings; propagating one spec sentence closes three).
+3. **Fan out in parallel**, one agent per unit, each owning all of that unit's findings.
+4. **Verify** everything was actually fixed.
+
+### Measured on the round-7 blocker set (100 open, 2026-08-28)
+
+- 47 cross-package / structural, 53 self-contained — step 2 is half the work, not a
+  pre-step. Plan for it as a phase, not a warm-up.
+- 60 distinct files but only 30 packages; 37 files carry exactly one finding.
+- Step 3 fans out to 20 packages, ~2.6 findings each, largest bucket 7.
+
+### Amendments (each earned by something that happened during round 7)
+
+1. **Partition by package, not by file.** Nearly every fix touches a source file *and* its
+   test file (`fork.go`+`fork_test.go`, `kind.go`+`kind_test.go`). Per-file assignment
+   guarantees two agents fighting over one test file. The coverage gate is also per-package
+   (exactly 100% for `internal/fsm/*`), so an agent cannot verify its own work unless it
+   owns the package. Packages are disjoint, so merges are trivial.
+2. **Isolate every agent in its own worktree, at a path the orchestrator mints.** During the
+   round-7 sweep three sibling reviewers applied mutations *in place* in the live tree
+   (`store_jsonl.go`, `review.go`, `builder.go`); any agent measuring in that window measured a
+   mutated baseline. Read-only reviewers survived it. Fix agents would commit each other's
+   mutations.
+
+   Saying "use your scratchpad" is not enough, and on 2026-08-27 it failed again: nine reviewers
+   were told that, several independently chose the same `$SCRATCH/mr`, and three reported finding
+   a sibling's edits (`export_test.go`, `cli/run.go`, a stray `zz_scratch_test.go`) in what they
+   believed was a clean copy. One produced phantom failures until it rebuilt from `git archive`.
+   The residue is worse than the wasted work: those runs reported intermittent failures in
+   `internal/fsm/{cli,kind,machine}` at roughly 1 in 4, a different test each time and never
+   reproducible in isolation — which reads exactly like a product race and was almost certainly
+   concurrent mutation of a shared copy. A collision does not announce itself; it arrives
+   disguised as a flaky test in the code under review.
+
+   So the orchestrator hands each agent a **unique, already-distinct path** rather than a
+   convention to follow — a timestamp and pid (`mut-<task>-$(date +%s)-$$`) or the agent's own
+   task id, minted by the caller and passed in the prompt. Agents cannot coordinate on a naming
+   scheme they each interpret separately, and the one that guesses wrong corrupts everyone's
+   measurements, not just its own.
+3. **Verify per agent, not only at the end.** "The suite passes" is not verification: on this
+   branch `O_NOFOLLOW`, the `ERR_RUN_ESCALATED` exit row and `Prune`'s keep-hash were each
+   deletable with the whole repo green. Each fix needs a failing test written first and a
+   recorded mutation kill. A single end pass also loses the mapping from a late defect back
+   to the agent that introduced it, because every source edit re-cuts the shard plan.
+4. **Re-derive step 3 assignments after step 2 lands** — structural fixes move line numbers
+   and delete findings, so an up-front assignment sends agents chasing stale locations.
+
+### Why this is a workflow, not a new engine
+
+The FSM already has the parts: `exec: subagent` fans out in-session, `exec: inline` is the
+serial case, and gates plus convergence already sequence phases. This is a `fix-fanout`
+workflow beside `sdlc-loop`, not new machinery. Pairs naturally with the mutation-testing
+TODO above, which supplies the per-agent verification step.

+Caveat on the sample: 8 of the 100 findings had already been fixed on the branch, so
+they are stale and correctly read as "not real" now (`record.go` is one, rejected by
+both arms). The comparison is between arms, not against ground truth.

+### Recommendation
+
+Not a default: 5.7x cost for one correction in ten is a bad trade when the cheap arm
+already sees the right hunks. Two better shapes, both measurable:

+1. **Escalation.** Run the cheap arm first; re-judge in the sandbox only when the
+   finding names other files, or when the cheap arm REJECTS (a false reject silently
+   drops a real bug, a false confirm only costs a human a look).

+   repo including `.git`. Setting `cmd.Dir` to a scoped tree is worth doing on its own
+   merits even if the evidence still arrives in the prompt.

+### If it is built

+- Record the evidence mode plus `(base_sha, head_sha, tree_hash)` on every `llm_call`:
+  content-addressing the tree keeps replay honest when the input text no longer
+  determines the verdict.
+- `fsm diff --a --b` must refuse or flag a cross-mode comparison: a judge that browsed

+## Verifying delegated fixes — measured, and NOT yet enforced anywhere
+
+**Status: measured 2026-08-29. Currently prose only. Nothing in the repo enforces it.**
+
+### What was measured
+
+Nineteen findings were delegated to lightweight (Haiku) agents in two batches: eleven
+documentation corrections, then eight of the harder "X is untested" class. Each agent was
+told the deliverable was a DEMONSTRATED MUTATION KILL, not a test: apply the mutation, show
+the suite passing (proving the guard unpinned), restore, write the test, re-apply, show it
+failing, and report both outputs.
+
+Result: 16 of 19 items were genuinely fixed. Three were not:
+
+1. A doc agent invented an error "code 151" that exists nowhere in the package.
+2. A doc agent reported a finding "already correct" having checked that the spec matches a
+   comment in the code — but the finding was that BOTH make the same false claim. It verified
+   consistency where correctness was asked.
+3. A fix agent **left its mutation in the production file** (`run.go`, the `MockTainted`
+   guard deleted), reported "No production behavior changed", and reported a passing
+   mutation kill for a test that does not kill it. Three of its four items were genuine; the
+   fourth was a fabricated result sitting on top of a regression it had introduced.
+
+All three were caught, every time by the same thing: re-running the mutation independently.
+
+### The conclusion, which is not "use a bigger model"
+
+Capability changes the error RATE, not the error CLASS. On the same day, working on the same
+branch, the orchestrating model (Opus) produced SIX fixtures that passed for the wrong reason
+— a regression test one character short, an id rejected as malformed before size was checked,
+a hash that differed because a file was absent rather than because the revision is hashed, a
+memoization test with a single candidate, a leak-check marker that was a substring of its own
+content, a cap test repeating one path — plus two verification mutations so weak they only
+broke the build on an unused import. More errors than any single Haiku agent. They did not
+ship only because mutation testing ran.
+
+So the deciding variable is whether an independent check runs, not who wrote the fix.
+
+### The protocol (to be enforced, not described)
+
+1. **A claimed mutation kill is not evidence.** Re-run every mutation with something that did
+   not write the test. This caught 3 of 3 problems at negligible cost.
+2. **A mutation must compile.** A deletion that breaks the build on an unused import "fails"
+   for a useless test too. Mutate to a different valid value instead.
+3. **The working tree must be clean of production changes after a test-only task.**
+   `git diff --exit-code -- <production paths>` — the near-miss above was one `git diff` away
+   from being caught automatically.
+4. **Agents mutate a scratch copy, never the live tree.** Half the round-7 reviewers did this
+   unprompted; the one that did not nearly shipped a regression.
+5. **Escalate on demonstrated failure, not on a guess about which class is hard.** Same shape
+   as judge escalation: cheap first pass, escalate what fails verification.
+
+### Why this belongs in the product
+
+metareview already gates review. It does not gate the FIX, and the fix is where a regression
+enters. Rules 1-4 are mechanical and cheap; none needs a model. A `metareview verify-fix`
+that re-runs a recorded mutation and refuses a dirty tree would make the protocol real
+instead of a paragraph someone remembered to put in a prompt.
+
+## The fix phase — deferred from 0.9.0, and the spine of 0.10.0
+
+**Status: TODO. Decided 2026-08-29 to defer rather than grow PR #13 further.**
+
+### What exists today, and why it is not enough
+
+`sdlc-loop` has a `fix` node, but it is a single `agent-edit` running `exec: inline` whose
+output is `{commit, summary}`. The FSM therefore *trusts the orchestrator's word* that a fix
+happened. Nothing records what the fix pins, nothing proves the fix holds, and `verify` asks an
+LLM ("still-present") whether the bug is gone when a deterministic proof is available.
+
+That is the same defect the whole round-7 review kept finding, one level up: a process everyone
+believes is in force, held by nothing.
+
+### The shape
+
+```
+fix     → agent-edit, output gains  pins: [{file, from, to, test}]
+verify  → mutation-verify (new kind): for each pin, apply from→to, run the test, REQUIRE fail;
+          restore, REQUIRE pass; then require the tree clean of production changes
+```
+
+Model-agnostic by construction: no judge in the loop. The LLM `still-present` check stays as a
+COMPLEMENT for bugs no test can pin, never as a replacement.
+
+Reuses machinery that already exists rather than inventing: the `cmd` kind already runs declared
+commands through `cmdexec` with consent hashing and audit; gates are already deterministic
+snapshot predicates; `TreeHash` and `repo_mode: enforcing` already detect unsanctioned edits.
+
+### Constraints, each earned the hard way
+
+- **Mutate a scratch worktree, never the live tree.** On 2026-08-29 a fix agent left its
+  mutation in `run.go` (the `MockTainted` guard deleted), reported "No production behavior
+  changed", and reported a kill its test does not achieve. One `git diff` would have caught it.
+- **A mutation must compile.** A deletion that breaks the build on an unused import "fails" for
+  a useless test too. Two of the orchestrator's own verification mutations had this flaw.
+- **A claimed kill is not evidence.** Re-run every mutation with something that did not write
+  the test. See the verification-protocol section above.
+- **Parallel fix agents partition by PACKAGE, not file.** A fix and its regression test live in
+  two files, and the coverage gate scores the package.
+
+### Enforcement, and its prerequisite
+
+`metareview status --json` (shipped in 0.9.0) is the contract a host hook branches on: `blocked`,
+`must_clear`, exit 1. The Claude Code and Codex hooks are thin shims over it, which is what keeps
+enforcement model-agnostic. Still needed:
+
+- **`--target` scoping.** `blocked` currently spans the whole review history: measured at 66
+  entries on this repository, which would block an agent on work it never touched.
+- **A bounded escalation path.** A Stop hook that always blocks is a livelock. Wire it to the
+  FSM's existing attempt cap and `ESCALATED` terminal rather than inventing a second mechanism.
+- **Precision is a safety property here, not just quality.** A blocked agent cannot self-clear -
+  `override grant` must come from outside, by design - so every false blocker costs a human
+  interrupt. Run 3 rejected 38% of candidates; run 5, after the rubric and evidence work, 14%.
+  That work is a PREREQUISITE for enforcement, not an adjacent improvement.

+
+Raised by CodeRabbit on PR #21, which read the committed shard results for the
+fsm-enhancements review (`blockingCount` nonzero, verdict `NEEDS_REVISION`) alongside a

+

+- nothing detects them being deleted, edited, or silently never fixed;
+- `metareview status` cannot report them, because it reads the findings store;
+- the only thing tracking the 41 blockers from the 0.9.0 post-merge review is prose in a PR

+evidence and is load-bearing in conversation, while no mechanism reads it. The fix is to ingest
+shard results into the findings store when the gate aggregates them, with the shard hash as
+provenance, so an unfixed blocker keeps blocking and a resolved one records `fixedInRunId`.

+## Evidence receipts do not bind to a source revision
+
+Raised by CodeRabbit on PR #21. `evidence.Receipt` records command, cwd, exit code, timestamps
+and stdout/stderr hashes — but nothing identifying the tree the command ran against. A receipt
+therefore proves a command succeeded *somewhere*, not that it succeeded on the code under
+review, and evidence generated at one commit can be presented unchanged for another. On this
+very PR the committed evidence went stale the moment further commits landed, and no gate noticed.
+
+Add `sourceRevision` to the schema and have the pr-ready and task-done gates refuse evidence
+whose revision does not match the context head. Until then, the revision is carried in the
+receipt `summary` by convention, which nothing enforces.
+
+## SelectDiff's budget is not a cap, and nothing reports a cut
+
+Found while fixing the inverted truncation term in `ContextForClaim` (PR #21). Two measurements,
+both on the same fixture:
+
+- `SelectDiff(diff, "pkg/b.go", 0, 133)` returned **40102** bytes; the same call with an unbounded
+  budget returned **39983**. A smaller budget produced a larger result, so `budget` is not a cap
+  and "select twice, compare lengths" cannot detect a cut.
+- `ContextForClaim` over a two-file claim carried in full produced **40193** bytes from a
+  **40074**-byte diff, because each selection re-emits its own `diff --git` header. So
+  `len(out) < len(diff)` — the current truncation test — reads a complete context as complete only
+  by luck, and reads some genuinely cut ones as complete too.
+
+`DiffTruncated` is the only signal telling a judge it is not seeing the whole story, and it is
+currently computed by that length comparison. Fixing it properly means settling what `budget`
+promises and having `SelectDiff`/`ContextFor` report whether they dropped content, rather than
+inferring it downstream. The inverted `!ok` term has been removed (it never changed an answer),
+but the signal underneath is still an approximation and should not be trusted for anything
+load-bearing until this is done.

+package findings

+import (
+	"crypto/sha256"
+	"encoding/hex"
+	"os"
+	"path/filepath"
+	"regexp"
+	"sort"
+	"strings"

+
+// Override bindings. A granted override is an exception to a particular state of the code, not a
+// permanent hole in the gate: it is bound to what justified it, and lapses when that changes.
+//
+// This is what makes unattended operation safe. Before it, `overridden` was terminal - the only
+// transition was into it - and an overridden record counted as "active existing" during
+// reconciliation, so a later run that rediscovered the same fingerprint filed nothing at all. One
+// grant silenced that check on that target permanently, and every exception an autonomous loop
+// took was a check it could never get back.
+const (
+	// BoundPaths: the finding named files that exist, and the exception lapses when their
+	// contents change. This is the precise case - unrelated commits leave the exception alone.
+	BoundPaths = "paths"
+	// BoundHead: the finding named nothing watchable, so the exception is bound to the commit it
+	// was granted at and lapses on the next one. Noisier, and deliberately so: a gate that cannot
+	// work out what to watch must fail toward blocking rather than stay silent.
+	BoundHead = "head"
+)
+
+// hashFile is a seam so the failure path is testable without depending on filesystem permissions.
+var hashFile = func(path string) (string, error) {
+	body, err := os.ReadFile(path) // #nosec G304 -- path is repo-relative and checked by bindablePaths
+	if err != nil {
+		return "", err
+	}
+	sum := sha256.Sum256(body)
+	return hex.EncodeToString(sum[:]), nil
+}
+
+// pathish matches a path-shaped token: at least one slash, and an extension. Findings in this
+// repository carry their file information in the fingerprint far more often than in Evidence.Path,
+// which frequently holds a pattern ("TODO|FIXME") or a marker ("diffTruncated") rather than a path.
+var pathish = regexp.MustCompile(`[A-Za-z0-9_.\-]+(?:/[A-Za-z0-9_.\-]+)+\.[A-Za-z0-9]+`)
+
+// bindablePaths returns the repo-relative files this finding names that actually exist. A path
+// that resolves to nothing is not watchable: binding to it would produce a hash that never
+// changes, which is a permanent override wearing the costume of a bound one.
+func bindablePaths(root string, record Record) []string {
+	seen := map[string]bool{}
+	var out []string
+	consider := func(raw string) {
+		for _, m := range pathish.FindAllString(raw, -1) {
+			clean := filepath.ToSlash(filepath.Clean(m))
+			if clean == "" || seen[clean] || strings.HasPrefix(clean, "..") || filepath.IsAbs(clean) {
+				continue
+			}
+			if info, err := os.Stat(filepath.Join(root, filepath.FromSlash(clean))); err != nil || info.IsDir() {
+				continue
+			}
+			seen[clean] = true
+			out = append(out, clean)
+		}
+	}
+	consider(record.Fingerprint)
+	for _, e := range record.Evidence {
+		consider(e.Path)
+	}
+	sort.Strings(out)
+	return out
+}
+
+// bindingFor computes what an exception on this record is an exception to.
+func bindingFor(root string, record Record, head string) (kind string, paths []string, hash string) {
+	paths = bindablePaths(root, record)
+	if len(paths) == 0 {
+		return BoundHead, nil, strings.TrimSpace(head)
+	}
+	h := sha256.New()
+	for _, p := range paths {
+		sum, err := hashFile(filepath.Join(root, filepath.FromSlash(p)))
+		if err != nil {
+			// Unreadable now, whatever it was at grant time: treat as a change, which lapses the
+			// exception rather than preserving it over a file nobody can inspect.
+			sum = "unreadable"
+		}
+		_, _ = h.Write([]byte(p + "\x00" + sum + "\n"))
+	}
+	return BoundPaths, paths, hex.EncodeToString(h.Sum(nil))
+}
+
+// lapseStaleOverrides returns granted overrides to `open` when what they were granted over has
+// changed. Grant provenance is kept: the audit has to be able to say that an exception existed,
+// who granted it, and why it stopped applying.
+func lapseStaleOverrides(root string, records []Record, run Run, now string) []Record {
+	for i := range records {
+		record := records[i]
+		if record.Status != StatusOverridden || !sameRunTarget(record, run) {
+			continue
+		}
+		head := record.GitHead
+		if record.OverrideBoundKind == BoundHead {
+			head = run.GitHead
+		}
+		kind, paths, hash := bindingFor(root, record, head)
+		if kind == record.OverrideBoundKind && hash == record.OverrideBoundHash {
+			continue
+		}
+		records[i].Status = "open"
+		records[i].OverrideLapsedAt = now
+		records[i].UpdatedAt = now
+		records[i].OverrideBoundKind = kind
+		records[i].OverrideBoundPaths = paths
+		records[i].OverrideBoundHash = hash
+	}
+	return records
+}

+		t.Fatal(err)
+	}
+	if err := os.WriteFile(p, []byte(body), 0o644); err != nil {
+		t.Fatal(err)
+	}
+}

+	GoModule string `json:"go_module"`
+	Files    []struct {

+		Mutations []struct {
+			Type   string `json:"type"`
+			Status string `json:"status"`

+// ParseGremlins normalises a gremlins JSON report.
+//
+// The status mapping is where the engine's vocabulary meets ours, and the important row is
+// TIMED OUT: gremlins omits it from its summary entirely, so a caller trusting that summary sees
+// a run in which those mutants never existed. Here it becomes Unresolved, which counts against
+// the score and makes the run incomplete.
+func ParseGremlins(data []byte, target string) (Report, error) {
+	var raw gremlinsReport
+	if err := json.Unmarshal(data, &raw); err != nil {
+		return Report{}, fmt.Errorf("mutation: parsing gremlins report: %w", err)
+	}
+	r := Report{Engine: "gremlins", Target: target}
+	for _, f := range raw.Files {
+		for _, m := range f.Mutations {
+			r.Mutants = append(r.Mutants, Mutant{
+				Status:   gremlinsStatus(m.Status),
+				File:     f.FileName,
+				Line:     m.Line,
+				Column:   m.Column,
+				Operator: m.Type,
+			})
+		}
+	}
+	return r, nil
+}

+func gremlinsStatus(s string) Status {
+	switch strings.ToUpper(strings.TrimSpace(s)) {
+	case "KILLED":
+		return Killed
+	case "LIVED":
+		return Survived
+	case "NOT COVERED", "NOT_COVERED":
+		return Uncovered
+	case "NOT VIABLE", "NOT_VIABLE", "SKIPPED":
+		// The mutant could not be built or was deliberately skipped: nothing was measured, and
+		// nothing is claimed. Not a kill.
+		return Unresolved
+	default:
+		// TIMED OUT, RUNERROR, and anything a future version adds. Defaulting to Unresolved is
+		// deliberate: an outcome this code does not recognise must never be scored as a success.
+		return Unresolved
+	}

+// Package mutation turns a mutation-testing engine's output into findings the gate can act on.
+//
+// It deliberately does not trust an engine's own score or exit code. Measured on 2026-08-29,
+// gremlins reported "Killed 10, Lived 0, Test efficacy: 100.00%" and exited 0 for a package in
+// which ten mutants had survived and ninety-seven were unresolved: its JSON summary has no field
+// for the unresolved class, and its efficacy is killed/(killed+lived), so unresolved mutants
+// leave both the numerator and the denominator. The worse the configuration, the better the
+// score. Totals are therefore computed here, from the per-mutant list, for every engine.
+package mutation
+
+import (
+	"fmt"
+
+	"github.com/dsifry/metareview/internal/findings"
+)
+
+// Status is the outcome of one mutant, normalised across engines.
+type Status string
+
+const (
+	// Killed: a test failed, so the mutation was detected. The only good outcome.
+	Killed Status = "killed"
+	// Survived: every test passed with the code deliberately broken. A real gap.
+	Survived Status = "survived"
+	// Uncovered: no test executes this code, so no mutation was run. Cheapest to find and the
+	// shape of most "guards that cannot fail"; a decided outcome, not an unknown.
+	Uncovered Status = "uncovered"
+	// Unresolved: the engine could not decide — timed out, errored, was killed mid-flight. NOT a
+	// kill. A run containing any of these has not measured what it claims to have measured.
+	Unresolved Status = "unresolved"
+)
+
+// Mutant is one mutation site and what became of it.
+type Mutant struct {
+	Status   Status `json:"status"`
+	File     string `json:"file"`
+	Line     int    `json:"line"`
+	Column   int    `json:"column,omitempty"`
+	Operator string `json:"operator"`
+	// Detail carries whatever the engine said about this mutant, e.g. a diff of the change.
+	Detail string `json:"detail,omitempty"`
+}
+
+// Report is one engine's run over one target.
+type Report struct {
+	Engine  string   `json:"engine"`
+	Target  string   `json:"target,omitempty"`
+	Mutants []Mutant `json:"mutants"`
+}
+
+// Score is the honest summary: every class counted, nothing folded away.
+type Score struct {
+	Killed     int
+	Survived   int
+	Uncovered  int
+	Unresolved int
+	// Efficacy is killed / (killed + survived + unresolved). Unresolved mutants count AGAINST the
+	// score rather than vanishing from it, so an under-configured run cannot outscore a careful
+	// one. Uncovered sites are excluded: no mutation ran, so there is nothing for a test to catch,
+	// and they are reported in their own right instead.
+	Efficacy float64
+}
+
+// Complete reports whether the run decided every mutant it attempted. A run that did not is not a
+// measurement, and no threshold should be applied to it.
+func (s Score) Complete() bool { return s.Unresolved == 0 }
+
+// Score counts the report. It reads only the per-mutant list.
+func (r Report) Score() Score {
+	var s Score
+	for _, m := range r.Mutants {
+		switch m.Status {
+		case Killed:
+			s.Killed++
+		case Survived:
+			s.Survived++
+		case Uncovered:
+			s.Uncovered++
+		default:
+			s.Unresolved++
+		}
+	}
+	if denom := s.Killed + s.Survived + s.Unresolved; denom > 0 {
+		s.Efficacy = float64(s.Killed) / float64(denom)
+	}
+	return s
+}
+
+// Findings turns every actionable outcome into a finding. A killed mutant is not actionable and
+// produces nothing; the other three each name a file and line a human can go to.
+func (r Report) Findings() []findings.Input {
+	out := make([]findings.Input, 0, len(r.Mutants))
+	for _, m := range r.Mutants {
+		var title, what, expected, recommend string
+		severity := "medium"
+		switch m.Status {
+		case Killed:
+			continue
+		case Survived:
+			title = "Surviving mutant: " + m.Operator
+			what = fmt.Sprintf("%s:%d was mutated (%s) and every test still passed.", m.File, m.Line, m.Operator)
+			expected = "A test fails when this code is deliberately broken."
+			recommend = "Add or strengthen a test that fails under this mutation, or delete the code if nothing depends on it."
+		case Uncovered:
+			title = "Uncovered mutation site: " + m.Operator
+			what = fmt.Sprintf("%s:%d is executed by no test, so no mutation could be run there.", m.File, m.Line)
+			expected = "Every line the gate is asked to trust is executed by at least one test."
+			recommend = "Cover the line, or remove it."
+			severity = "low"
+		default:
+			title = "Undecided mutant: " + m.Operator
+			what = fmt.Sprintf("%s:%d could not be decided by %s (timeout or engine error).", m.File, m.Line, r.Engine)
+			expected = "Every attempted mutant is decided; an undecided one is not evidence of anything."
+			recommend = "Raise the engine's timeout until nothing is undecided, then re-run. Do not treat this as a kill."
+			severity = "high"
+		}
+		out = append(out, findings.Input{
+			Reviewer:       "mutation-" + r.Engine,
+			Severity:       severity,
+			Classification: "blocking",
+			Title:          title,
+			Finding:        what,
+			Expected:       expected,
+			Found:          m.Detail,
+			Recommendation: recommend,
+			Evidence:       []findings.Evidence{{Type: "mutant", Path: m.File, Line: m.Line}},
+			Fingerprint:    fmt.Sprintf("mutation:%s:%s:%s:%d", m.Status, m.Operator, m.File, m.Line),
+		})
+	}
+	return out
+}
